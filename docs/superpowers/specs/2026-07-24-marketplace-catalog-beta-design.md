# Каталог маркетплейсов — beta-редизайн («Витрина каталога»)

Дата: 2026-07-24. Статус: тестовая страница, одобрена к сборке в режиме
«свобода действий» (пользователь явно делегировал дизайн-решения).

## Задача

Текущая `/marketplaces/listings/` — server-rendered список широких карточек без
фото, с полной перезагрузкой на каждый фильтр. Нужна «ВАУ»-версия: стильная,
быстрая, удобная для продавца с сотнями SKU. Пользователь явно разрешил смену
стека («если условный vue или react даст свободу — будем переводить потихоньку»).

## Решение

Отдельная тестовая страница `GET /marketplaces/listings/beta`, существующая
страница не трогается.

- **Стек**: Vue 3 через CDN (jsdelivr, `vue.global.prod.js`), без бандлера —
  инвариант «Jinja2 + Tailwind CDN + без bundler» не нарушен, но появляется
  реальная реактивность и путь постепенной миграции. Alpine-оболочка base.html
  сосуществует: Vue монтируется в свой subtree, Vue-разметка внутри
  `{% raw %}` (не конфликтует с Jinja).
- **Данные**: только существующий JSON API `/marketplaces/listings/api`
  (фильтры/пагинация) и detail JSON `/marketplaces/listings/<id>`
  (Accept: application/json). Одно безопасное расширение бэкенда: list-сериализатор
  `MarketplaceListing.to_public_dict()` дополняется bounded полем
  `primary_image` (первый URL из уже публичного `media_json`) — без него
  витрина с фото невозможна без N+1 detail-запросов.
- **Синк Ozon**: существующий `POST /accounts/<id>/sync` (JSON + X-CSRFToken),
  компактные пилюли кабинетов в командной строке вместо блока карточек.

## Дизайн (в системе «Тёплая редакция», только токены)

- **Подпись страницы**: товарная «полка» — grid карточек с фото 3:4,
  канальный рельс цвета `--mp-wb`/`--mp-ozon`, letter-tile fallback для карточек
  без фото (первая буква названия, Instrument Serif, канально-тонированный фон
  через color-mix). Счётчик товаров в шапке — Instrument Serif (редкий
  display-акцент, разрешён системой).
- **Командная строка** (sticky): поиск (hotkey `/`), канальный переключатель в
  стиле `.sh-channel-bar` (клиентский, один селектор кабинета на страницу),
  статус-чипы со счётчиками (Все/Активные/Модерация/Ошибки/Архив — счётчики
  через параллельные `per_page=1` запросы, это и есть «статистика» страницы,
  KPI-плиток нет), фильтр связи, тумблер «недоступные», переключатель вида
  Сетка/Таблица (persist в localStorage).
- **Quick view drawer**: клик по карточке — правая панель с detail JSON: фото,
  идентификаторы, статусы, цены (все значения price_summary), остатки по типам,
  ошибки модерации, связь с общей карточкой, времена синка, CTA «Открыть
  деталь». Read-only, ничего не пишет.
- **Клавиатура**: `/` — поиск, стрелки — выбор карточки, Enter — drawer,
  Esc — закрыть.
- **Движение**: каскадное появление первых ~14 карточек (28ms шаг), hover-lift
  с `--shadow-2` и лёгким зумом фото, drawer `--dur-3`/`--ease-out`; всё
  гасится `prefers-reduced-motion`.
- **Статусный бейдж** показывается только на НЕ-активных карточках
  (тишина = норма); недоступные — grayscale + бейдж.
- Пустые состояния: «нет листингов вообще» → CTA синка/подключения;
  «фильтры ничего не нашли» → кнопка сброса. Ошибка API → баннер с retry.

## Файлы

- `routes/marketplace_listings.py` — тонкий route `beta()` (аккаунты+синки в
  bootstrap JSON).
- `models.py` — `primary_image` в list-сериализаторе.
- `templates/marketplace_listings_beta.html`, `static/marketplace-catalog-beta.css`,
  `static/marketplace-catalog-beta.js`.
- Тесты: рендер beta 200/403 в `tests/test_marketplace_listing_routes.py`,
  primary_image в сериализаторе.

## Явно НЕ делаем

Никаких write-действий кроме существующего синка; никакого второго медиа-мастера
(картинка — bounded URL из наблюдённого snapshot); старая страница и её роуты
не меняются; бандлер не вводится.
