# Фикс бага: у поставщика «Андрей» ровно 3 фото на всех карточках

- Дата: 2026-06-16
- Статус: утверждён к реализации (надёжный фикс парсера + конфиг)
- Связанные документы: [Фича «Качество карточек»](2026-06-16-card-quality-rating-design.md)

## 1. Симптом

У всех карточек поставщика «Андрей» (`code='andrey'`, sex-opt.ru) ровно 3 фотографии, хотя их должно быть больше.

## 2. Корневая причина (высокая уверенность)

Обрезание происходит на **этапе парсинга/импорта**, не на отображении.

1. Маппинг колонок Андрея задаёт фото-поле, читающее ровно три колонки:
   `migrations/migrate_add_sexopt_supplier.py:58-62`
   ```json
   {"photo_urls": {"columns": ["image", "image1", "image2"], "type": "photo_urls"}}
   ```
   (`SUPPLIER_CODE='andrey'`, `SUPPLIER_NAME='Андрей (sex-opt.ru)'`, `:25-26`).
2. Парсер `services/supplier_service.py:431-441` (ветка `field_type == 'photo_urls'`) проходит **только** по `config['columns']` и ничего сверх перечисленного не подбирает. Резолв имён колонок в индексы — `:360-402`; ненайденные имена просто пропускаются с предупреждением.
3. Поэтому в `SupplierProduct.photo_urls_json` максимум 3 URL. Весь downstream работает корректно и без капа:
   - `routes/photos.py:88,91` — `generate_public_photo_urls` = `range(len(photo_urls))`, без ограничения;
   - `services/wb_product_importer.py:131,696` — грузит полный список;
   - `services/wb_content_payload.py` — фото вообще не трогает.

Это **специфично для Андрея**: легаси-поставщик `sexoptovik` использует `_parse_sexoptovik_photos` (`supplier_service.py:611-632`) с неограниченным перечислением. Срезы `[:3]` в `supplier_service.py:2181,2268` и `infographic_renderer.py:441,700` — выбор обложки для инфографики, к списку фото карточки и WB-загрузке отношения не имеют (исключено).

## 3. Подтверждение перед фиксом

БД в чекауте устаревшая (нет таблиц `suppliers`/`supplier_products`) — проверять на рабочей среде.

1. Заголовки живого фида: `csv_source_url` Андрея (`migrate_add_sexopt_supplier.py:149-156`, `https://old.sex-opt.ru/catalogue/db_export/?type=csv&...`) — перечислить все колонки, матчащие `image*`. Доступ к фиду может требовать `auth_login`/`auth_password` поставщика.
2. Прод-БД:
   ```sql
   SELECT sp.external_id, json_array_length(sp.photo_urls_json) AS n
   FROM supplier_products sp JOIN suppliers s ON s.id = sp.supplier_id
   WHERE s.code = 'andrey' ORDER BY n DESC LIMIT 20;
   ```
   Ожидаем все `n = 3`.

**Развилка по данным:** если фид реально отдаёт только `image/image1/image2` — 3 фото это предел поставщика, не баг кода (тогда фикс не нужен, проблема上游). Если колонок больше (`image3..imageN`) — баг в маппинге, чиним. Если URL лежат в одном столбце через разделитель (`;`/`,`) — нужен split-тип поля, а не фикс-колонки.

## 4. Фикс (надёжный: парсер + конфиг)

### 4.1 Парсер (основное, future-proof для всех header-based поставщиков)

`services/supplier_service.py:431-441`, ветка `photo_urls`:

- добавить авто-обнаружение колонок по префиксу: помимо явных `columns`, подхватывать любые заголовки, матчащие шаблон (по умолчанию `^image\d*$`), из `header_index`;
- сделать шаблон настраиваемым опцией маппинга `columns_prefix` (или `columns_pattern`);
- обработать случай одной колонки с разделителем: если значение содержит `;`/`,` — split в список URL;
- сохранить обратную совместимость: если заданы только `columns` без префикса/паттерна — поведение прежнее.

### 4.2 Конфиг Андрея

- расширить маппинг (`migrate_add_sexopt_supplier.py:60`) реальными колонками `image3..imageN` (по результату §3) ИЛИ перейти на `columns_prefix: "image"`;
- идемпотентная миграция UPDATE-ит существующего поставщика (`:162-178`);
- альтернативно — правка вживую через админ-роут `routes/suppliers.py:3665` / `Supplier.csv_column_mapping` (`models.py:2184`).

### 4.3 Бэкафилл

Повторный импорт каталога Андрея, чтобы `photo_urls_json` пересоздались со всеми фото; проверить, что `generate_public_photo_urls` отдаёт >3 URL и WB-карточка несёт их.

## 5. Тестирование

- Юнит-тест парсера `_extract_fields_by_mapping` / `photo_urls`-ветки:
  - явные `columns` (обратная совместимость) → прежний результат;
  - `columns_prefix` + заголовки `image, image1..image7` → 8 URL;
  - одна колонка с `;`-разделителем → список;
  - отсутствующие колонки → не падает.
- Проверка идемпотентности миграции (повторный прогон).
- После бэкафилла — sanity-запрос §3.2 показывает `n > 3`.
