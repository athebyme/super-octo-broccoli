# «Фотостудия»: генерация инфографики и доп. фото для карточек WB

Дата: 2026-07-14. Статус: одобрена; Phase 0 реализован в коде
(`feature/infographics`, план `docs/superpowers/plans/2026-07-14-infographics-phase0-pilot.md`),
пилот завершён. Решение Phase 1 зафиксировано: production использует только
background-only generation + локальный pixel-preserved foreground composite +
детерминированный fact-safe текст. i2i и model-rendered text остаются
research-only. Реализация и runbook: `docs/INFOGRAPHICS_PILOT.md`.

## Проблема

Карточкам не хватает фото: часть каталога ниже целевого `min_photos`, галереи
однообразны (только фото поставщика), инфографики нет. Ручная подготовка слайдов
для сотен карточек в месяц нереальна. Домен платформы — товары для взрослых:
готовые генеративные сервисы либо режут такие фото цензурой, либо дают текст с
ошибками в кириллице. Требование заказчика: текст на слайдах — строго без ошибок.

## Зафиксированные требования

- Только свой магазин, объём 100–1000 карточек/мес.
- Основа слайда — реальное фото поставщика + AI-обработка (не полная генерация товара).
- Флоу: пакетная генерация → очередь ревью → загрузка на WB после одобрения.
- Оплата: рубли (RU-агрегаторы) либо посредники/крипта для зарубежного.
- На карточку: 1 платная hero-генерация + бесплатные шаблонные слайды;
  опционально 1–3 платных доп. композитных фото для добивки количества.
- Интеграция только с единым ИИ-помощником (unified orchestrator);
  legacy-агенты (`photo-optimizer` и пр.) не используются и не расширяются.
- Логотип/название магазина добавляются на слайды по кнопке.
- 18+: фото проходят цензуру моделей и модерацию WB, но остаются
  «завлекательными» — эмоции через свет/фактуры/атмосферу, не через эротику.
- Спорные пункты (модель, режим, API vs self-host) решает пилот (Phase 0).

## 1. Скоуп и цели

Два типа генерации для карточек (домен 18+):

- **Инфографик-комплект**: 1 hero-слайд (товар в AI-сцене) + 3–4 шаблонных
  слайда (фото + преимущества текстом). Текст и логотип кладёт Playwright-рендерер
  (`services/infographic_renderer.py`, выход 900×1200) — ошибки в кириллице
  исключены архитектурно: нейросеть текст не рисует.
- **Доп. композитные фото** (без текста): 1–3 атмосферных кадра, чтобы добить
  количество фото до целевого (`ProductDefaults.min_photos` уже существует)
  и разнообразить галерею.

Флоу: выбор товаров (страница или чат-помощник) → пакетная генерация в фоне →
очередь ревью → approve → загрузка на WB. Никаких legacy-агентов.

Qwen-Image-Edit против hosted-моделей на наших товарах; решает пилот.

## 3. Ключевое решение для 18+: два режима hero

- **Режим A — i2i edit**: фото товара → модель рисует сцену вокруг
  (Kontext/Seedream/NB/Qwen). Красиво и интегрированно, но фильтры могут
  отклонять интим-товары на входе.
- **Режим B — «чистый фон + локальный композит»**: t2i генерит фон **без товара
  вообще** («шёлк, свечи, будуар» — любая модель это пропустит), товар вырезается
  локально (rembg, бесплатно) и компонуется поверх в Playwright с тенью.
  Ноль отказов по цензуре, пиксели товара нетронуты; минус — сцена чуть менее
  «сросшаяся».
- Промпт-стратегия: пресеты атмосфер (будуар/неон/люкс/спа), нейтральная лексика
  («аксессуар», «флакон»), санитайзер промпта. Эмоции — через свет и фактуры.

### Текст на слайдах: три уровня надёжности

Свежие открытые чекпоинты Qwen (Qwen-Image-2512 от 31.12.2025 и
Qwen-Image-Edit-2511 от 23.12.2025, оба Apache 2.0) рендерят кириллические
глифы нативно — впервые «текст от модели» перестал быть заведомо
неприемлемым. Но «строго без ошибок» на длинных русских фразах при
100–1000 карточек/мес остаётся вероятностью, а не гарантией, поэтому текст
делится на три уровня:

1. **Программный текст + CSS/SVG-эффекты** (Playwright, бесплатно, 100 %
   надёжность): неон-glow через `text-shadow`, градиентная заливка букв,
   обводка/тиснение, декоративные кириллические шрифты, blend-mode, чтобы
   надпись подхватывала свет AI-сцены. Дефолт для всех фраз преимуществ
   и любого длинного текста.
2. **Стилизация нашего текста моделью**: точный текст рендерится пиксельно
   (Playwright) → Qwen-Image-Edit одевает буквы в эффект («неоновые трубки»,
   «шёлковая лента», «высечено в камне»), глифы заданы входной картинкой и
   не генерируются с нуля — искажения редки, но результат идёт через ревью.
   Для заголовка hero-слайда.
3. **Свободная генерация текста моделью** (Qwen-Image-2512): только короткие
   крупные слова и цифры («−30 %», «ХИТ», «NEW», имя бренда); промпт на
   английском, целевой текст кириллицей в кавычках. Длинные фразы этим
   уровнем не делаются.

Уровни 2–3 стоят как обычная генерация (та же 1 картинка) и всегда проходят
ревью-очередь с кнопкой «перегенерить».

**Phase 0 — пилот** (`scripts/infographic_pilot.py`, one-off, `SKIP_SCHEDULER=1`):

- Ветка API: 20–30 реальных товаров × {FLUX.2, Kontext Pro, Seedream 4.5,
  Nano Banana, режим B}. Бюджет ~500–1000₽.
- Ветка GPU: те же товары через Qwen-Image-Edit (Lightning и fp8) на 2–3 часах
  H100/H200 в immers.cloud. Бюджет ~1000–1300₽.
- Ветка текста: на тех же GPU-часах прогнать уровни 2–3 (стилизация заголовков
  Edit-2511, короткие слова 2512) на 10–15 русских фразах разной длины.
- Метрики: % отказов цензуры, сохранение товара (пиксели/форма/цвет), качество
  сцены, % искажений кириллических глифов на уровнях 2–3, фактическая скорость
  и ₽/картинка.
- По итогам выбираем: primary-модель, дефолтный режим (A/B), допустимые уровни
  текста и стратегию API vs self-host vs гибрид.

## 4. Данные и файлы

- Новая идемпотентная миграция (`migrations/`), подключить к
  `docker-entrypoint.sh` fail-fast (ORM читает таблицы сразу после старта):
  - `InfographicBatch`: seller_id, параметры (тип комплекта, пресет атмосферы,
    режим A/B, модель, логотип on/off), статус, agent_task_id, usage/стоимость.
  - `InfographicItem`: batch_id, `entity_kind` + product_id, статусы
    `pending → generating → review → approved → uploaded / rejected / filtered /
    failed`, slides_json (пути + типы слайдов), снапшот прежнего набора фото WB
    (для ручного отката), usage/стоимость по item.
- Файлы: `data/infographics/{seller_id}/{item_id}/slide_N.png`
  (по паттерну `content_photo_cache`).
- Брендинг: logo-файл + текст магазина + дефолтный toggle в настройках продавца
  (рядом с `global_media`).

## 5. Провайдер-слой

Расширение существующего `services/image_generation_service.py`:

- Новый метод `edit_image(source, prompt, opts)` в фасаде.
- Адаптеры Gen-API и AITunnel (простые HTTP, рубли, ключи per-seller как сейчас).
- Адаптер `SelfHostEndpoint` — тот же контракт `edit_image` поверх HTTP-эндпоинта
  на арендованном GPU (ComfyUI/минимальный сервер); появляется только если пилот
  выберет self-host, интерфейс закладываем сразу.
- Fallback-цепочка: primary → альтернативная модель → режим B → шаблонный слайд
  с пометкой `filtered`. Отказ классифицируется (NSFW/ошибка), максимум 2 платные
  попытки на слайд, timeout/retry/backoff по конвенциям репо.

## 6. Пайплайн (Python-owned, не model-owned)

Детерминированный skill в unified runtime через `AgentTask`: prefetch фото
(`photo_cache`) → тексты слайдов (существующий `ai_generate_rich_content`,
DeepSeek Flash, только если ещё нет) → hero-генерация → рендер шаблонов + лого
(`render_hybrid_slides`) → доп. фото (если заказаны) → сохранение → item в ревью.
Checkpoints на границе каждой карточки, cancellation перед каждым платным
вызовом, честные partial-результаты, бюджет батча в рублях/вызовах с жёсткой
отсечкой.

## 7. Интеграция с ИИ-помощником

- Read-skill **`photo-gap-audit`** (детерминированный SQL, zero-LLM): «товары,
  где фото < N», «без инфографики», фильтры по категории — collection-card,
  входит в `_CHAINING_SOURCE_SKILLS`, передаёт `selected_product_ids +
  entity_kind` дальше (как существующий `quality-audit`).
- Write-skill **`infographic-generate`**: план → подтверждение пользователем →
  создаёт batch. Tool allowlist минимальный; генерации и записи — Python-путь.
- Internal API: typed endpoints `infographics/batches` (agent-auth, tenant scope,
  лимит IDs, строгая валидация уникальных positive integer IDs — по batch-
  инвариантам AGENTS.md).

## 8. Ревью и загрузка на WB

Страница `/infographics` («Тёплая редакция», обе темы, `.sh-*`-компоненты):

- Очередь батчей → карточка item: все слайды рядом, per-slide
  approve/reject/перегенерить (платно только hero/доп-фото), toggle логотипа
  (мгновенный локальный пере-рендер), bulk approve.
- При approve — выбор позиции (в начало карточки / в конец), загрузка
  существующим `upload_photos_to_card`, verify по образцу `/supplier-updates`,
  кнопка «вернуть прежние фото» из снапшота.
- Фото-путь не отключает rollback контента (инвариант AGENTS.md).

## 9. Тесты

Selection-SQL и tenant denial; строгая валидация batch IDs; адаптеры на mock
HTTP (успех/NSFW/timeout); fallback-цепочка; рендер с лого (smoke); переходы
статусов ревью; изоляция ошибок при загрузке (savepoint); идемпотентность
миграции. Без реальных WB/API/LLM вызовов.

## 10. Фазы

- **0**: пилот-скрипт (API-ветка + GPU-ветка) + отчёт → выбор модели, режима и
  стратегии API/self-host/гибрид (1–2 дня + ~2 000₽ бюджета проб).
- **1**: миграция, провайдер-слой, пайплайн, страница ревью, загрузка на WB,
  логотип. Запуск со страницы товаров.
- **2**: skills для ИИ-помощника (audit + chaining + запуск из чата),
  доп. композитные фото, пресеты эмоций.
- **3**: автоматизация (авто-предложение для новых импортов), метрики;
  при выборе гибрида — оформленный batch-раннер для GPU-сессий.
