# Дизайн: редизайн UI/UX «Качество карточек» + движок авто-улучшения

- Дата: 2026-06-17
- Статус: утверждён к реализации
- Ветка: `feature/card-quality-rating`
- Связанные документы: [Фича «Качество карточек» (исходная)](2026-06-16-card-quality-rating-design.md)

## 1. Цель и контекст

Базовая фича «Качество карточек» уже работает (см. исходный дизайн): WB-рейтинг (`productRating` 0–10 / `feedbackRating` 0–5) + детерминированный Quality Score 0–100 с разбивкой по 8 измерениям + рекомендации + страница `/card-quality` со slideover-деталью и трендом. Но текущий UI — плоская таблица с inline-стилями (`templates/card_quality.html`), не использующая дизайн-систему сайта и готовые макросы. Фича изолирована: продавца к ней ничто не подводит, а «улучшить» сводится к запуску диагностических агентов, которые лишь советуют текстом.

Эта итерация делает три вещи:

1. **Редизайн под язык сайта** — тёплый минимализм (фон `#faf9f7`, тёмный hero `#0a0a0a`, акцент-терракота `#c45d3e`, Instrument Serif для цифр/заголовков, Inter для текста, скругление 8px, без теней), кокпит-триаж вместо плоской таблицы.
2. **Движок «Предложить → Подтвердить»** — агент готовит структурированный дифф «было → стало» по управляемым измерениям; продавец применяет в один клик (одиночно и массово); запись в WB через существующий путь публикации.
3. **Подсказки во флоу** — виджет на дашборде, бейджи + фильтр в списке товаров, тосты, чтобы продавец сам приходил к слабым карточкам.

### 1.1 Что именно «улучшается» (честная модель)

Править карточку = поднимать **наш Quality Score** (контролируемые 8 измерений). Звёздный WB-рейтинг (`nm_rating`/`wb_feedback_rating`) приходит из продаж и отзывов — его нельзя поднять редактированием карточки, он растёт косвенно. Поэтому весь копирайт говорит про Quality Score и дельту («Quality 42 → 78»), а не «рейтинг подскочит».

Управляемость измерений авто-движком:

| Измерение | Вес | Источник улучшения | Авто? |
|---|---|---|---|
| characteristics | 25 | characteristics-filler / данные поставщика (ImportedProduct) | да |
| photos | 20 | photo-optimizer (порядок) + enrichment (доп. фото поставщика) | частично |
| description | 15 | seo-writer | да |
| title | 10 | seo-writer | да |
| brand | 10 | brand-resolver | да |
| barcodes | 10 | данные поставщика / sizes | подсказка |
| price | 5 | модуль цен (не AI-переписывание) | подсказка |
| category | 5 | category-mapper | да |

## 2. Решения, зафиксированные на брейншторме

- **Визуальное направление:** кокпит-триаж (тёмный hero + кольцо среднего Quality + полоса распределения здоровья; приоритетная зона «Требуют внимания» сверху; строки с мини-гейджем, WB-звёздами, чипами проблем и кнопкой «Улучшить»).
- **Авто-улучшение:** «Предложить → Подтвердить» (безопасно, обратимо, контроль у продавца). Никакого автопуша в WB без подтверждения.
- **Движок (архитектура):** Вариант ① — переиспользовать enrich-дифф и существующий путь применения, **без новой staging-таблицы**. Предложения живут в `AgentTask.result_data` (он персистится в БД), аудит и откат — через существующий `CardEditHistory`. Отдельную таблицу-очередь (`CardImprovementProposal`) откладываем до момента, когда реально понадобится workflow «копится пачка предложений на потом».
- **Точки подсказок:** все — виджет на дашборде, бейджи + фильтр в списке товаров, страница-триаж, тосты.

## 3. Архитектура UI

### 3.1 Кокпит `/card-quality` (полный редизайн `templates/card_quality.html`)

Переписываем шаблон на дизайн-систему `sh-*` и макросы `score_gauge`/`wb_rating_badge` (`templates/macros/components.html:274,289`). Убираем дублирующие inline-реализации гейджа/бейджа.

**Структура страницы (Alpine.js `cardQualityPage()`):**

1. **Hero** (`sh-page-header`, тёмный): заголовок «Качество карточек», подзаголовок; действия `Обновить рейтинги` (есть) + `⚡ Улучшить слабые` (новое, bulk).
2. **Сводная лента** (`sh-card`): слева большое кольцо `score_gauge(avg_quality, 96)`; в центре **полоса распределения здоровья** — горизонтальный сегментированный бар (poor/average/good/excellent) с числами и легендой; справа WB-бейджи `wb_rating_badge` (0–10 и 0–5) + крупно «Требуют внимания: N».
3. **Триаж-лист** (`sh-card--flush`), две группы:
   - **«Требуют внимания · N»** — раскрыта; карточки `quality_score < 50` ИЛИ `nm_rating < 6`, сортировка по quality по возрастанию.
   - **«В порядке · N»** — свёрнута, «показать все».
   Строка триажа: миниатюра фото (первое из `photos_json`) → артикул + название → мини-`score_gauge(quality, 40)` → `wb_rating_badge` → **чипы проблем** (`sh-badge`, измерения со статусом `warning`/`error`: «фото», «характеристики», «описание»…) → действия `[Улучшить]` `[Детали]`. Левый акцент-бордер у слабых, hover-состояние, скелетоны при загрузке.
4. **Slideover-деталь** (`sh-slideover sh-slideover--lg`): радиальный `score_gauge(quality, 96)`; WB-бейджи + «обновлено N»; **разбивка по 8 измерениям** — для каждого подпись + полоса прогресса `barColor(status)` + подсказка `hint` + вес; **тренд** Chart.js (как сейчас, оставляем); блок действий `⚡ Улучшить карточку` + `🤖 Глубокий AI-анализ` (текущий). После «Улучшить» — инлайн-дифф «было→стало» с чекбоксами и `Применить выбранное`.

**Empty / loading:** скелетоны строк при первой загрузке; `empty_state` если каталог пуст; явная подсказка «запусти Обновить рейтинги» когда нет данных синка.

### 3.2 Поток «Предложить → Подтвердить»

```
[Улучшить] (строка или slideover)
   └─ POST /api/card-quality/<id>/improve
        ├─ бэкенд: по слабым измерениям выбирает агенты (seo-writer/characteristics-filler/brand-resolver/category-mapper/photo-optimizer)
        ├─ создаёт задачи через agent_service.create_task(...)
        └─ возвращает task_ids → UI поллит статус (как текущий ai-analyze)
   └─ когда готово: result содержит proposal = {field: {current, proposed, dimension, source_agent}}
        └─ UI рендерит дифф «было→стало» с чекбоксами (стиль product_enrich.html)
   └─ [Применить выбранное] → POST /api/card-quality/<id>/apply {fields:[...]}
        ├─ EnrichmentService.apply_enrichment(...) / WildberriesAPIClient.update_card(merge_with_existing=True)
        ├─ запись CardEditHistory (snapshot_before/after, wb_synced) — аудит/откат бесплатно
        ├─ пересчёт quality_score + quality_breakdown_json, точка в CardRatingHistory
        └─ ответ {old_quality, new_quality} → тост «Quality 42 → 78»
```

**Массовое улучшение** `⚡ Улучшить слабые`:
- Прогон `improve` по top-N слабых (N конфигурируемо, дефолт 20–30, ограничение озвучить в UI — без молчаливого усечения).
- Общий экран подтверждения в стиле `prices_batch_confirm.html`: категории (например, безопасные авто-поля vs требующие внимания), список карточек с диффом, чекбоксы.
- `Применить выбранное` пачкой → переиспользуем `apply_enrichment` с `bulk_edit_id` (уже поддерживается) + `BulkEditHistory` для трекинга статуса/отката.

### 3.3 Источник структурированных предложений

Генеративные/обновляющие агенты уже умеют отдавать структуру — образец `seo-writer.batch_result_schema` (`{results:[{product_id,title,description,keywords}]}`) + `_map_structured_result_to_updates` (`agents/catalog/seo_writer.py:84,122`). План:

- Добавить/переиспользовать у каждого профильного агента **single-режим со структурированным результатом** (предлагаемые новые значения полей), а не текстовые рекомендации.
- Бэкенд-оркестратор (новый, напр. `services/card_improver.py` или роут) собирает результаты нескольких агентов в единый `proposal` под слабые измерения карточки и маппит на поля через существующий маппер.
- Диагностические агенты (card-doctor) остаются как «глубокий AI-анализ» (мнение/риски), не подмешиваются в дифф.

## 4. Подсказки во флоу

### 4.1 Виджет на дашборде
- В `dashboard()` (`seller_platform.py:453`) добавить агрегат качества (или фронт грузит через новый `GET /api/card-quality/summary`).
- Карточка `.dash-*` (стиль из `dashboard.html`): мини-`score_gauge` среднего Quality + «N карточек тянут рейтинг вниз» + полоска распределения + CTA `Разобрать →` на `/card-quality`.
- Новый лёгкий эндпоинт `/api/card-quality/summary` — общий хелпер с агрегацией из `/api/card-quality/list` (`routes/card_quality.py:46-58`), вынести расчёт в функцию, чтобы не дублировать SQL.

### 4.2 Список товаров
- `products_list` (`seller_platform.py:1298`) + `templates/products.html`:
  - Новая колонка **«Качество»** — компактный бейдж по `quality_score` (цвет по статусу, ссылка/открытие детали качества). Переиспользуем существующий паттерн цветных бейджей рейтинга (`products.html:524-527`).
  - Добавить `'quality_score': Product.quality_score` в sort-dict (`seller_platform.py:1436-1447`).
  - Фильтр **«Только слабые»**: `quality_score < 50` ИЛИ `nm_rating < 6` (порог вынести в константу, согласовать с `need_attention` в `card_quality.py`).
- `Product.quality_score` / `quality_breakdown_json` уже в модели (`models.py:221-222`), сейчас не выводятся — задействуем.

### 4.3 Тосты / инлайн-подсказки
- Минимально и по делу, чтобы не спамить:
  - Успех улучшения — тост с дельтой Quality (через `$store.toasts`).
  - На странице товара/деталях со слабой карточкой — мягкий `alert_box` (инлайн), а не всплывающий тост.

## 5. Бэкенд / данные

### 5.1 Новые/изменённые роуты (`routes/card_quality.py`)
- `POST /api/card-quality/<id>/improve` — оркестрация агентов под слабые измерения, возврат `task_ids`; результат поллится существующим `/agents/api/tasks/<id>/status`.
- `POST /api/card-quality/<id>/apply` — применить выбранные поля proposal; вернуть `{old_quality, new_quality, wb_synced}`.
- `GET /api/card-quality/summary` — агрегат для дашборд-виджета (общий хелпер с list).
- Bulk-варианты: `POST /api/card-quality/improve-weak` + экран/`POST .../apply-batch` (через `BulkEditHistory`).
- Все роуты — seller-scoped (фильтр `seller_id=current_user.seller.id`), как существующие.

### 5.2 Переиспользуемое (не изобретать заново)
- `EnrichmentService.apply_enrichment(product, imp, fields, photo_strategy, seller, wb_client, bulk_edit_id=...)` (`services/supplier_enrichment.py:456`) — применение правок + WB + история.
- `WildberriesAPIClient.update_card(nm_id, updates, merge_with_existing=True)` (`services/wb_api_client.py:757`).
- `CardEditHistory` (snapshot_before/after, changed_fields, wb_synced) (`models.py:465`) — аудит/откат.
- `BulkEditHistory` + `can_revert()` (`models.py:391`) — массовые операции.
- `build_preview()` / стиль `product_enrich.html` — UI диффа с чекбоксами.
- `agent_service.create_task` / `complete_task` / `task.to_dict()`; `_map_structured_result_to_updates`.
- Макросы `score_gauge`, `wb_rating_badge`; `prices_batch_confirm.html` как образец bulk-подтверждения.

### 5.3 Пересчёт Quality Score
- После apply — `compute_card_quality(product_to_card_input(product))` (`services/card_quality_scorer.py`), персист `Product.quality_score` + `quality_breakdown_json` + `quality_checked_at`, добавить точку в `CardRatingHistory`.
- Закрепить, что quality персистится (сейчас `card_quality_detail` считает на лету; синк-джоб пересчитывает) — apply должен обновлять БД, чтобы бейджи/виджет/список были консистентны без полного синка.

## 6. Объём и фазы

- **Фаза 1 — Редизайн кокпита + slideover.** Чистый визуал на `sh-*`/макросах, триаж-лист, распределение здоровья, скелетоны. Низкий риск, без записи в WB.
- **Фаза 2 — Движок «Предложить → Подтвердить» (одиночный).** `improve`/`apply`, структурированные предложения агентов, инлайн-дифф, пересчёт quality, тост с дельтой.
- **Фаза 3 — Bulk + точки подсказок.** `Улучшить слабые` + экран подтверждения; виджет на дашборде; колонка/фильтр в списке товаров; тосты/инлайн-алерты.

Каждую фазу можно мёрджить отдельно.

## 7. Тестирование

- **Юнит (stdlib unittest, как в проекте):**
  - Оркестратор маппинга proposal: слабые измерения → набор агентов; слияние результатов агентов в `{field:{current,proposed,dimension,source}}`.
  - Хелпер summary (агрегаты avg/распределение/need_attention) — на фикстурах Product.
  - Пересчёт и персист quality_score после apply.
- **Интеграционные/ручные:**
  - `apply` пишет в `CardEditHistory`, `wb_synced` корректен, откат работает.
  - Поллинг статуса задач improve в UI.
- **Визуальная проверка** (Playwright/скриншот): кокпит, slideover, дифф, виджет дашборда, бейдж в списке — на тестовом продавце с данными.

## 8. Риски и решения

- **Агент вернул кривое значение.** Защита: всё проходит через подтверждение (никакого автопуша); чекбоксы по полям; `CardEditHistory` даёт откат.
- **WB API упал на apply.** `apply_enrichment` уже различает `wb_sync_success`; показываем частичный успех; не теряем БД-состояние.
- **Спам тостами.** Тосты только на действие пользователя (apply), пассивные подсказки — инлайн-алерты.
- **Молчаливое усечение bulk.** Явно сообщать «обработано top-N из M», как требует анти-паттерн «no silent caps».
- **Рассинхрон quality.** apply персистит quality в БД, не полагаясь на следующий синк.

## 9. Out of scope (YAGNI)

- Отдельная таблица-очередь `CardImprovementProposal` и инбокс «сохранить на потом» (Вариант ②) — откладываем.
- Полностью автономный автопуш в WB без подтверждения (Вариант «авто вживую») — отклонён по безопасности.
- Генерация изображений (только переупорядочивание/подтягивание фото поставщика).
- Прямое «поднятие» звёздного WB-рейтинга — невозможно через API.
