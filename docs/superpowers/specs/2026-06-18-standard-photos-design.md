# Дизайн: «Стандартные фото» — расширение медиа-дефолтов продавца

- Дата: 2026-06-18
- Статус: утверждён к реализации
- Ветка: `feature/card-quality-rating`
- Связанные документы: [Редизайн «Качество карточек»](2026-06-17-card-quality-ui-redesign-design.md)

## 1. Цель и контекст

У части карточек мало фото — это бьёт по конверсии и по фото-измерению Quality Score. Нужно дать продавцу простой способ держать в ЛК библиотеку **стандартных фото** (бренд-баннер, размерная сетка, инфографика по уходу и т.п.), задавать их **позицию** (всегда первая / последние) и **режим** (всегда закреплять / добивать только когда фото мало), применимых **глобально или по категориям WB**, и применять их к существующим карточкам.

### 1.1 Что уже есть (переиспользуем, не плодим новое)

`ProductDefaults` (`models.py:904`) уже содержит:
- Поле `global_media` (JSON-список загруженных медиа) + хелпер `get_global_media_list()`.
- Разделение **global / category** через `rule_type` + `wb_subject_id`/`wb_category_name`.
- UI на `/settings/product-defaults` (вкладка «Медиа»): drag-drop загрузка, сетка превью, отдача через `product_defaults_serve_media`. Хранилище `data/global_media/<seller_id>/`.
- Применение медиа **при импорте** новых карточек (`services/wb_product_importer.py:2948`).

`WildberriesAPIClient` уже умеет порядок:
- `upload_photos_by_url(nm_id, photo_urls, seller_id)` → `POST /content/v3/media/save` `{nmId, data:[url,…]}` — заменяет набор в УКАЗАННОМ ПОРЯДКЕ; чтобы добавить — передаём и существующие, и новые URL.
- `upload_photos_to_card(nm_id, photo_paths, seller_id)` → media/file (по X-Photo-Number).

### 1.2 Чего не хватает (объём работы)

1. Позиция/режим/порядок у каждого стандартного фото.
2. Порог «мало фото».
3. Композиция итогового упорядоченного набора для карточки.
4. Применение к **существующим** карточкам (сейчас только импорт) — через card-quality «Улучшить» + bulk.
5. Публичный (без авторизации) URL отдачи стандартных фото — чтобы WB media/save сам забрал картинку.

## 2. Решения брейншторма

- Источник фото: **загрузка файлов в ЛК** (как сейчас в global_media).
- Применение: **предложение в «Улучшить» (с подтверждением) + bulk** «дополнить слабым».
- Логика: **пины всегда + добивка когда мало**.
- Модель: **расширяем `ProductDefaults.global_media`** (а не отдельная таблица).
- Дефолт порога «мало фото»: **4**.

## 3. Данные (без миграции схемы — `global_media` это JSON)

Каждый элемент `global_media` (JSON) расширяется полями:
- `position`: `'first' | 'last'` (дефолт `'last'`).
- `mode`: `'pin' | 'fill'` (дефолт `'fill'`). `pin` = всегда добавлять; `fill` = только когда у карточки мало своих фото.
- `order`: `int` — порядок внутри своей группы (first/last).
- (существующие: `filename`, `original_name`, `type`, `size`.)

Порог «мало фото»: новое **поле-колонка** `min_photos` на `ProductDefaults` (nullable, дефолт логики = 4). Берётся из глобального правила продавца. Требует короткой миграции колонки (паттерн `_run_startup_migrations`/`add_*` как в проекте). `type` остаётся — применяем только `type=='photo'` (видео не позиционируем).

Обратная совместимость: старые элементы без новых ключей трактуются как `position='last'`, `mode='fill'`, `order=0`.

## 4. Композиция итогового набора

Новый модуль `services/standard_photos.py`:

```
compose_card_photo_urls(product, seller) -> list[str]:
    own = текущие фото карточки (URL из photos_json)
    applicable = media глобального правила (rule_type='global')
               ∪ media правила категории (rule_type='category', wb_subject_id == product.subject_id)
    sparse = len(own) < min_photos(seller)            # min_photos из глобального правила, дефолт 4
    photos = [m for m in applicable if m.type == 'photo']
    first = [m for m in photos if position=='first' and (mode=='pin' or sparse)] отсортированы по order
    last  = [m for m in photos if position=='last'  and (mode=='pin' or sparse)] отсортированы по order
    result = [public_url(m) for m in first] + own + [public_url(m) for m in last]
    дедуп по URL, сохранить порядок; обрезать до WB-лимита (30)
    return result
```

- `public_url(m)` — публичный URL стандартного фото (см. §6).
- Если `result == own` (нечего добавлять) — композиция возвращает пустой результат/флаг «без изменений».
- Чистая функция над данными (media-list + own + min_photos) — юнит-тестируема.

## 5. Применение

### 5.1 В «Улучшить» (per-card, с подтверждением)
- В `POST /api/card-quality/<id>/improve` (или в сборке proposal) добавляется `photos`-предложение: `current` = own, `proposed` = `compose_card_photo_urls(...)`, `dimension='photos'`, `source='standard-photos'` — если есть что добавить.
- UI slideover показывает превью итогового порядка (было→стало) с чекбоксом.
- На «Применить» → `upload_photos_by_url(nm_id, proposed_urls, seller_id)` → обновить локальный `photos_json` → `CardEditHistory` → пересчёт quality. Реализуется в `apply_card_updates` (поле `photos` уже в `ALLOWED_FIELDS`): для `photos` использовать media/save по URL (а не только локальную запись), т.к. теперь у нас есть упорядоченный список URL.

### 5.2 Bulk «Дополнить фото слабым карточкам»
- Кнопка/страница: собрать карточки с `len(own) < min_photos`, для каждой скомпоновать и применить через `upload_photos_by_url`, трекинг через `BulkEditHistory`. Явно «обработано N из M».

## 6. Публичная отдача стандартных фото

WB media/save забирает картинку по URL сам, без наших cookс. Текущая отдача `product_defaults_serve_media` — `@login_required`. Добавляем **публичный read-only** маршрут, напр. `GET /media/standard/<seller_id>/<filename>` (без авторизации, без листинга каталога, имена файлов — uuid). Отдаёт файл из `data/global_media/<seller_id>/`. `public_url` строится от внешнего домена (`DOMAIN`/конфиг). Существующий приватный маршрут для UI-превью остаётся.

## 7. ЛК UI (вкладка «Медиа» на `/settings/product-defaults`)

- У каждого загруженного фото: селектор **Позиция** (Первая/Последняя), селектор **Режим** (Всегда / Если мало), drag-сортировка (order).
- Поле **«Минимум фото»** (порог) в глобальном правиле.
- Те же контролы в правилах по категориям.
- Сохранение — расширить существующие `save-global` / `save-category` / `upload-media` роуты, чтобы принимать position/mode/order/min_photos.
- Подсказка: «Эти фото добавляются к карточкам: всегда (Режим=Всегда) или когда у карточки меньше N фото (Режим=Если мало). Порядок: Первая идёт в начало, Последняя — в конец».

## 8. Тестирование

- **Юнит (stdlib unittest):**
  - `compose_card_photo_urls`: пины всегда; fill только при sparse; порядок first/own/last; дедуп; кап 30; обратная совместимость старых элементов; merge global ∪ category.
  - `min_photos` чтение из глобального правила + дефолт.
  - Парсинг/сохранение position/mode/order в global_media (роуты save).
- **Интеграционные/ручные:** применение через `upload_photos_by_url` (мок WB); публичный media-роут отдаёт файл и не требует логина; bulk top-N.
- **Визуальная проверка:** вкладка «Медиа» с новыми контролами; photos-предложение в slideover; bulk-страница.

## 9. Риски и решения

- **WB мин. размер 700×900** — валидировать при загрузке (Pillow), предупреждать продавца; не пушить недомерки.
- **media/save заменяет весь набор** — всегда включаем существующие URL карточки в правильном порядке (own в середине).
- **Публичная отдача файлов** — только read-one-file по uuid-имени, без листинга; не отдавать произвольные пути (защита от path traversal через `secure_filename`/whitelist).
- **WB-лимит 30 фото** — обрезаем, в UI предупреждаем если пины+own превышают.
- **Видео** — на первом этапе позиционируем только `type=='photo'`; видео из global_media не трогаем.

## 10. Out of scope (YAGNI / на будущее)

- Vision-модель для оценки/генерации изображений (отдельная будущая фича — у агентов нет такой модели).
- Авто-применение без подтверждения (только импорт уже делает это; для существующих карточек — только подтверждённые пути).
- Редактор/кроп изображений в браузере.
