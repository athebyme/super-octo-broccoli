# Единый мультимаркетплейсный фронт Seller Hub — дизайн

Дата: 2026-07-16. Статус: принят к реализации.

## Проблема

Ozon-интеграция добавлена «сбоку»: в сайдбаре пункты «X Ozon» вшиты в WB-группы
(5 отдельных `{% if MARKETPLACE_OZON_ENABLED %}` в `base.html`), у одного концепта
две страницы (Качество/Качество Ozon, Аналитика/Обзор Ozon, Финансы/Финансы Ozon,
Отзывы WB/Ozon, Цены/Цены и остатки Ozon, Синхронизация+История/Операции Ozon).
Пайплайн «поставщик → публикация» неявно WB: импорт без выбора канала,
«Мои товары» показывает только WB-статусы, bulk-действия только WB,
`/supplier-updates` полностью WB. Четыре Ozon-страницы (finance, quality,
analytics, fulfillment) и две админки не переведены на токены «Тёплой редакции».

## Целевая модель UX

Пользователь думает **задачами** (карточки, цены, отзывы, финансы), а не каналами.
Канал (WB / кабинет Ozon) — это измерение внутри задачи, а не отдельная страница
в меню.

### Сценарии

1. **Подключение** — `/api-settings` общая точка (WB ключ + Ozon кабинеты);
   расширенное управление кабинетами — `/marketplaces/accounts`.
2. **Импорт → публикация** — Каталог поставщиков → «Мои товары» (канонический хаб
   `ImportedProduct`) → публикация на WB (batch) и/или подготовка Ozon-черновиков
   (bulk) → Черновики Ozon → Операции. «Мои товары» показывает состояние карточки
   **во всех каналах** (колонка «Каналы»).
3. **Ведение** — Карточки/Качество/Цены/Отзывы/Аналитика/Финансы: одна страница
   концепта на канал, переключение через **channel bar**.

## Решения

### 1. Shell: channel bar (сигнатурный элемент)

- Jinja-макрос `channel_bar(...)` в `templates/macros/components.html`:
  пилюльный рельс `.sh-channel-bar` под шапкой страницы. Табы-ссылки:
  optional «Все каналы», «Wildberries», по одному табу на активный Ozon-кабинет
  (`Ozon` / `Ozon · Имя` при >1 кабинете), ghost-таб «Подключить Ozon» когда
  кабинетов нет. Активный таб = `--bg-card` + `--shadow-1`; маркетплейс
  идентифицируется точкой 8px (`--mp-wb` / `--mp-ozon`) + текстом (не только цветом).
- Данные для табов — глобальный контекст `mp_nav` (context processor,
  `services/marketplace_nav.py`): `ozon_enabled`, список активных Ozon-кабинетов
  текущего seller (кэш в `flask.g`, один SELECT на рендер, только для seller).
- Токены: `--mp-wb`, `--mp-ozon` в `base.html` (light/dark), приглушённые
  к тёплой палитре версии брендовых цветов. Только для идентификации каналов;
  не для статусов и не для графиков.
- При выключенном `MARKETPLACE_OZON_ENABLED` макрос не рендерит ничего —
  WB-страницы выглядят как раньше.

### 2. Навигация (сайдбар + ⌘K)

Группы по задачам, без пунктов-дублей «X Ozon»:

- Главная
- **Товары**: Карточки, Каталог маркетплейсов*, Качество, Фотостудия,
  Объединение, Блокировки
- **Операции** (новая группа): Синхронизация WB, История операций,
  Операции Ozon*
- **Цены**: Управление, Ценообразование, Мониторинг
- **Поставщики**: Каталог, Мои товары, Черновики Ozon*, Авто-публикация,
  Обновление карточек WB
- **Отзывы**: один пункт (channel bar внутри)
- Контент, Конкуренты, ИИ-помощник — без изменений
- **Аналитика**: Обзор, Финансы, Детальный P&L, Заказы Ozon* (внутри — табы
  заказы/возвраты/отмены), Отмены, Склад и возвраты, Регионы, Sentiment, Telegram
- **Настройки**: Дефолты товаров, API и подключения, Кабинеты Ozon*,
  Готовность маркетплейсов, Логи API, Стоп-слова

`*` — под `MARKETPLACE_OZON_ENABLED`. Удаляемые пункты: Каталог/Черновики/
Операции/Цены-остатки Ozon из «Товары», Качество Ozon, Обзор/Возвраты/Отмены/
Финансы Ozon из «Аналитика», группа-развилка «Отзывы». «Готовность маркетплейсов»
переезжает из «Товары» в «Настройки». ⌘K-палитра обновляется соответственно.

### 3. Channel bar — раскладка по страницам

| Концепт | WB-страница (таб «Wildberries») | Ozon (таб на кабинет) | «Все каналы» |
|---|---|---|---|
| Карточки | `/products` | `/marketplaces/listings?marketplace=ozon&account_id=N` | `/marketplaces/listings` |
| Качество | `/card-quality` | `/marketplaces/quality?account_id=N` | — |
| Цены | `/prices/` | `/marketplaces/commercial?account_id=N` | — |
| Аналитика | `/analytics` | `/marketplaces/analytics?account_id=N` | — |
| Финансы | `/finances` | `/marketplaces/finance?account_id=N` | — |
| Отзывы | `/reviews` | `/marketplaces/reviews?account_id=N` | — |
| Операции | `/products/sync-status` | `/marketplaces/operations?account_id=N` | — |

На Ozon insight-страницах channel bar заменяет самодельный тулбар
(кросс-кнопки + `<select account_id>`); на fulfillment-страницах — только табы
кабинетов (WB-аналога нет), внутренние табы Заказы/Возвраты/Отмены остаются.
Черновики Ozon channel bar не получают (стадия пайплайна, канально-специфична).

### 4. «Мои товары» — мультимаркетплейсный хаб

- Backend `seller_my_products()`: bulk-подгрузка Ozon-черновиков страницы
  (`MarketplaceProductDraft` по `imported_product_id in page_ids + seller`),
  сгруппированных по кабинету; счётчик черновиков для стат-строки.
- Колонка «Каналы»: WB-бейдж (по `import_status`) + бейдж на кабинет Ozon
  (черновик/готов/ошибка → ссылка на draft detail). Строка без черновика
  сохраняет per-row «Подготовить Ozon».
- Bulk-действие «Подготовить Ozon» для выбранных: новый endpoint
  `POST /marketplaces/drafts/bulk-prepare` (flag-gated, tenant-scoped, ≤200
  уникальных positive int IDs, CSRF) → `MarketplaceDraftProvisioner`
  (детерминированный, без LLM/provider) → flash-итог, redirect назад.
- Стат-строка: WB-статусы остаются честными («Готово к WB», «На WB»),
  при флаге добавляется карточка «Черновики Ozon» со ссылкой на `/marketplaces/drafts`.
- Шапка/фильтры переводятся на стандартные `.sh-*`.

### 5. Доводка сырых страниц до токенов

`marketplace_finance.html` (22 hex), `marketplace_quality.html` (20),
`marketplace_analytics.html` (12, графики → `window.shChart`),
`marketplace_fulfillment.html` (11), `admin_marketplaces.html`,
`admin_marketplace_categories.html` (чистый Tailwind) + зачистка остаточных hex
в `marketplace_accounts/commercial_detail/operation_detail/draft_detail/operations`.
Эталоны: `marketplace_listing_detail.html`, `marketplace_inbox.html`,
`admin_ozon_categories.html`. Правила: только токены/`.sh-*`/макросы, обе темы,
радиусы карточек ≤ 8px, статусы через `--ok/--warn/--danger/--info`.

### 6. Честные лейблы WB-специфики

Канально-специфичные инструменты не маскируются под общие: «Обновление карточек
WB» (страница остаётся WB — это её суть), «Синхронизация WB», чипы «Категория WB»
в каталоге поставщика остаются с явным «WB».

## Вне scope этой итерации

- Перевод `/products` на общий read model (P11 gate — backend-инвариант).
- Выбор целевого маркетплейса при импорте от поставщика (Ozon-черновики уже
  авто-провижионятся на каждый включённый кабинет; UI-выбор — отдельная итерация).
- Provider writes любого рода: вся работа — UI/навигация + один детерминированный
  локальный bulk-provision endpoint.
