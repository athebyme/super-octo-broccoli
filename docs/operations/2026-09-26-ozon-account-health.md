## Изменение

Новая Vue-страница «Состояние магазина» доступна из настроек каждого кабинета, в том числе отключённого. Подключение, обработчик очереди, шесть разделов и неподтверждённые операции показаны отдельно. Полная успешная загрузка не подменяется новой частичной попыткой; manual 7d не подтверждает автоматический 30d-период. Отзывы и вопросы имеют независимые 90d-состояния.

Обновление страницы — только локальный GET. Наблюдение не расшифровывает ключ, не вызывает Ozon/LLM, не ставит заявки, не повторяет отправку и не решает, можно ли публиковать товар. Сохранённый отказ в доступе не объявляется пустой лентой; неизвестный исход отправки остаётся в истории с точным состоянием проверки.

Singleton scheduler раз в 30 секунд пишет короткий атомарный heartbeat. Для healthy нужны одновременно свежий сигнал, занятый flock, совпадающие файл/PID/process birth. Просто существующий PID или недавний файл не подтверждает работу. Наблюдатель не выбирает нового владельца; схема относится к текущему одному host/container.

## Операторская проверка

```bash
docker exec -u app seller-platform python scripts/check_ozon_health.py --seller-id 2 --account-id 1
```

Команда не импортирует Flask runtime и читает SQLite в `mode=ro`. Exit **0** — у наблюдённых компонентов нет сигнала внимания, **1** — есть требующие внимания факты, **2** — полное наблюдение получить не удалось. Нельзя трактовать любой exit 1 как остановку сервиса: например, сохранённый отказ отзывов уже достаточен. JSON не содержит ключей, payloads, покупательского текста или process identity. Это не проверка полной readiness, backup или write eligibility.

1. **Нет HTTP, CLI доступна:** сопоставить Docker health и startup logs. Во время миграций не запускать второй экземпляр, не ставить вручную migration stamp и не перезапускать контейнер только из-за длительного ожидания.
2. **Scheduler stale/stopped/unknown:** проверить живой контейнер, его штатный singleton и executor/logs. Отсутствие сигнала не разрешает удалять lock или повторять записи. После восстановления нужен свежий heartbeat и продолжение durable queue.
3. **Раздел waiting:** смотреть срок паузы. Сохранённый Retry-After не сокращать; кнопка локальной проверки его не меняет.
4. **Access denied/expired:** различать права, сохранённый provider отказ и истечение ключа. Восстановление подключения делать через существующий UI; наличие grant не доказывает фактический доступ/тариф. Buyer price probes без новой информации не повторять.
5. **Unknown/expired operation:** открыть точную историю, сопоставить попытку и observed state. Не переотправлять изменение автоматически; действуют прежние proposal/reconciliation правила.

## Что остаётся открытым

Внешний монитор, владелец аварийных сигналов и автоматическая доставка alert не установлены. Разрешение владельца на редкие агентные сообщения в Telegram не расширено до периодических аварийных рассылок. Off-host/key/media recovery, RPO/RTO, полномасштабный downtime/cutover drill, representative финансовая сверка, real create/stock/reply pilots и длительный пользовательский пилот остаются открытыми. Покупательская цена и скидка Ozon по-прежнему неизвестны до подтверждённого источника.

Частные артефакты: `account-health-*` в локальном release directory; synthetic screenshots в `output/ozon-ui/account-health-*`. Реальные screenshots и диагностические JSON остаются в закрытом каталоге, не в Git.

Одно итоговое сообщение в настроенный deployment Telegram отправлено успешно. Периодическая рассылка не устанавливалась.
