# Покупательская цена Ozon: проект обращения в поддержку

Статус: подготовлен 25.09.2026; **не отправлен**. Отправить можно из поддержки нужного кабинета Ozon Seller. Ключи, токены и полные API-ответы к обращению не прикладывать.

## Текст обращения

Здравствуйте. Нужна помощь с доступом и действующим контрактом `POST /v1/product/prices/details` для нашего кабинета.

24.09.2026 метод вернул HTTP 403, `code=7` как с read-only ключом, так и с текущим ключом кабинета. При этом ответ `/v1/roles` для текущего ключа явно содержит `/v1/product/prices/details`. Обычные product-info и price-v5 reads работают. Запрос price-details передавал обязательное `skus` со SKU нашего товара, предварительно полученным из product-info; product_id вместо SKU не использовался. Записей или изменений товаров эта диагностика не делала.

Просим проверить фактический доступ нашего кабинета и пояснить:

1. Какие права, тариф или иные условия требуются этому методу? Почему он присутствует в `/v1/roles`, но возвращает 403? Просим назвать причину именно для нашего кабинета и доступное исправление.
2. Где доступна актуальная полная схема request/response? `docs.ozon.ru/api/seller/` 25.09.2026 около 07:18 UTC вернул 307 на себя, в обычном Chromium — 403 «Похоже, нет соединения». Просим прислать действующую спецификацию или доступную официальную ссылку.
3. Как получить для одного SKU базовую цену до скидок, цену после акций продавца и текущую покупательскую цену? Какие поля различают обычную цену, Ozon Карту, персональные купоны, регион и способ оплаты?
4. Какое поле или сопоставимая пара подтверждает скидку за счёт Ozon — её сумму и процент? Какова база расчёта, валюта, срок актуальности и смысл отсутствующих/нулевых значений? Просим подтвердить текущий статус поля `discount_percent`, если оно присутствует в контракте.
5. Если price-details недоступен этому кабинету, какой официальный Seller API метод или отчёт предоставляет эти сведения? Удалённый `marketing_price` из price-v5/product-info мы не используем.

Нам важно отдельно показывать акции продавца и скидку площадки. Общую разницу между зачёркнутой и текущей ценой не считаем скидкой Ozon. Подключать платные услуги автоматически не просим; сначала нужны условия и причина отказа.

## Что изменит следующий шаг разработки

- Подтверждённая схема и причина 403: проверяем необходимые настройки кабинета, отдельное решение владельца требуется только для платного подключения или изменения согласованного доступа.
- Доступ исправлен: один bounded read по собственному SKU через общий ledger; фиксируем только обезличенные метаданные и денежные факты с валютой/временем/условиями.
- Есть coherent наблюдение и подтверждена семантика: проектируем отдельный durable read scope, хранение provenance/freshness, затем подключаем общий price UI и проверяем живые товары с разными акциями.
- Доступа нет: seller price продолжает работать; buyer/скидка площадки остаются неизвестными. Это не считается завершением требования владельца.
