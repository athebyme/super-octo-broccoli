# Common content keyboard focus follow-up — 2026-10-01

This focused packet fixes focus loss after the common-content editor replaces controls in the plain DOM. Photo reordering now moves focus to the enabled opposite-direction arrow for the same photo at either end of the order. Returning from review restores focus to the fresh preview trigger after discarding the old preview. Mode/photo toggles, characteristic removal, product selection, and reset focus their replacement control or the nearest useful field control.

Refresh and successful save/readback restore focus only when focus began in the editor, the displayed product is still the expected product, and the user has not moved focus outside the editor. A refresh failure focuses its visible error after the busy/inert state clears. Re-rendering during refresh also recreated its refresh button as disabled; the action-state update now restores its enabled state when busy work ends. A successful save followed by a failed readback keeps the existing status message and focuses the refreshed field controls. No HTTP, preview-token, apply, or readback ordering changed.

`tests/ux01/common_product_content_focus_dom.js` runs the production editor code and delegated handlers against a small focus-aware DOM. It rejects focus on detached, disabled, hidden, or inert controls and resets `activeElement` when a focused node is removed. Its check IDs for the browser fixture are `common_photo_boundary_focus_first`, `common_photo_boundary_focus_last`, and `common_preview_cancel_focus_return`. It also checks local replacement actions, refresh success/error, save/readback behavior, fresh token use, and that async completion does not steal focus after the user moves outside the editor. The save case edits product 11, selects product 22, and verifies the existing apply transition back to changed product 11 before checking the restored field focus.

The harness accepts an optional production-script path so the pre-change module can be used for a negative regression proof. Against the `e44df45` module, it fails at `common_photo_boundary_focus_first` because the original code calls `focus()` on the moved photo's now-disabled up arrow. The current module passes the same harness. This verifies source-handler and synthetic DOM behavior, not a real browser layout.

The actual Chromium browser fixture remains unverified in this environment: earlier checks established that loopback socket binding and the Docker socket are denied. This packet does not bypass those restrictions or claim browser/viewport focus evidence. The separate browser fixture must still verify computed visible focus and the selected/empty responsive matrix before UX-01 browser acceptance is complete.
