# Ozon: рабочий интерфейс подготовки и исправлений

## Область

По запросу владельца улучшить удобство Ozon UI. Парсинг, тексты товаров,
общий каталог и работа параллельного агента исключены из изменения. Публикация,
tenant scope, подтверждения, проверки и повторы сохраняют существующие контракты.

Применены `frontend-design` (Anthropic, revision
`41bbe19d1a1a7eaab5e7bb9050a417e5c6cffc8f`) и `web-design-guidelines`
(Vercel, revision `063bee94c3f4df8453406c830b0a7df0f2860278`). Установлены
через штатный skill-installer вне репозитория; инструкции прочитаны полностью.
Правила Vercel прочитаны из официального `web-interface-guidelines/command.md`.

## Дизайн до реализации

Аудит исходного состояния:

- `templates/marketplace_drafts.html:178` — два статуса одной карточки,
  число ошибок без причины; создание одной карточки занимает первый экран.
- `templates/marketplace_draft_detail.html:178` — технические коды стоят перед
  объяснением; нет прямого перехода от замечания к соответствующему разделу.
- `templates/ozon_bulk_upload_detail.html:55` — десять равнозначных счётчиков
  и повторяющиеся пояснения отодвигают карточки и исправление вниз.
- `templates/ozon_bulk_upload_detail.html:6` — полная перезагрузка каждые
  15 секунд может сбрасывать чтение, фокус и открытые детали.

Аудитория — продавец, который обрабатывает партию товаров, а не изучает
устройство API. Основная задача экрана: увидеть препятствие и перейти к
конкретному исправлению, не потеряв кабинет.

Сохраняется «Тёплая редакция» из `base.html`, а не вводится новая тема:
фон `#faf9f7`, поверхность `#ffffff`, текст `#1a1a1a`, акцент `#c45d3e`,
граница `#e8e5e1`; в CSS используются только существующие переменные,
включая dark и semantic status variants. Рабочая типографика — Inter,
названия и пояснения выравниваются влево, числовые данные — tabular-nums.

Сравнение компоновок:

```text
Было                         Рабочая очередь
Большая шапка                Название + действие
Форма создания               Товары | Черновики | Загрузки
Фильтры                      Компактные фильтры
Статус + статус              Товар | что исправить | действие
Число ошибок                 Подготовить одну карточку [раскрыть]
```

Выбран рабочий список с явными причинами. Отказ от ещё одного dashboard с
KPI-плитками: продавцу здесь нужны карточки и исправления, а не обзор бизнеса.
На результате загрузки главным становится исправление партии; подробная
статистика и технические данные доступны по раскрытию. Разные статусы
отправки и неопределённый результат не объединяются с успехом.

## Проверка

Результаты реализации и проверок добавляются после выполнения. Скриншоты
с реальными карточками и диагностические данные хранятся вне Git.
