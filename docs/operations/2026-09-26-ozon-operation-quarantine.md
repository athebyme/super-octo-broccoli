## Зачем нужен пакет

Текущая кнопка остановки проверки отдельной publication operation оставляет результат Ozon `uncertain` и освобождает локальную квоту, но не останавливает другие product, price или stock writes по тому же provider identity. Кандидат добавляет отдельное решение продавца: после неизвестного результата одной физической попытки владелец видит сохранённые факты и явно ставит запрет на **новые изменения**. Это локальная мера, а не подтверждение успеха или отказа Ozon; результат исходной операции, attempt_count и snapshots не переписываются. Уже отправленная операция остаётся доступной для ручной read-сверки, автоматическая сверка поставленной на карантин операции останавливается.

Область вычисляется на сервере из сохранённой отправки. Согласованные exact offer ID и известный Ozon product ID ограничивают один товар выбранного кабинета; неизвестная или противоречивая identity требует отдельного явного подтверждения **всего кабинета**. Товарный запрет охватывает карточку и фото в составе полного product write, цену и остатки на всех складах. Проверка повторяется под account lock перед первой физической попыткой, включая queued dispatch, batch, rollback и новый idempotency key; уже attempted операции продолжают только прежнее чтение. Самостоятельная Ozon media write пока prepare-only и не объявляется запущенной. Другие кабинеты и WB не затрагиваются.

Решение и журнал `placed`/`note_added`/`released` хранятся отдельно в `MarketplaceWriteQuarantine` и `MarketplaceWriteQuarantineEvent`. Исторические uncertain операции не получают выдуманных решений. На `/marketplaces/operations/<id>/review` исход Ozon и локальная остановка показаны отдельно; потерянный POST сначала перечитывается, автоматического повторного решения нет. Заметка не снимает запрет. Снятие требует просмотра свежих версий и отдельного подтверждения **доказанного исхода той же исходной операции**. Commercial сверяется с exact confirmed/submitted state; failed task — с результатом своего item; archive — с exact архивированным offer/product; create/update — с сохранённым confirmed state, согласованным item, временем и fingerprint. Для update допускаются только записанные при штатной сверке узкие provider-нормализации `8229` (import-only «Тип») и `9024` (канонизация offer_id), с повторной проверкой всех остальных полей. Actual-workflow тест этого пакета доказал release path для `8229`; отдельного quarantine end-to-end сценария для `9024` и нового live-provider доказательства в этом выпуске нет. Проверка `9024` переиспользует ранее существующий узкий canonicalization contract, не заявляет новый эксперимент. Другая успешная операция, свободный текст, истечение времени или смена ключа не дают снять запрет. Снятие не создаёт новый запрос Ozon.

## Rollback и ограничения

Базовый rollback image — прежний `sha256:29a5f754e1599f3a03a9e154c76afd7bd1e49e9c915308fda507a8f6816d1eaf`. Additive таблицы и audit при runtime rollback не удаляются; live DB/WAL, Ozon rate ledger, credentials и исторические operation rows не откатываются. **Старый image не знает о карантине.** Read-only count `0` сам по себе не закрывает race: пользователь может создать hold до смены runtime. Сначала остановить новые operator decisions и provider mutations, затем под этой паузой прочитать persisted `active` holds и только после этого переключать runtime. Проще и безопаснее возвращать старый image со всеми тремя Ozon write flags `0` — publication, commercial и auto-publish — независимо от предварительного count. При любом active hold держать их выключенными до runtime с общим guard либо отдельного принятого решения по каждому запрету. Если после приёмки появится решение владельца, изучить его до отката; строки не удалять. Нулевые hold/event counts в read-only smoke не заменяют quiescence, проверку здоровья и protected state при откате.

Новый пакет не решает неизвестную buyer price/скидку Ozon, не вводит новый provider endpoint, не делает автоматический исход из ручной заметки и не разрешает blind retry после ambiguous write. Полный контракт и критерии проверки: [дизайн карантина](../design/ozon-operation-quarantine.md); действия оператора: [runbook](../OZON_PRODUCTION_RUNBOOK.md) и [руководство продавца](../OZON_USER_GUIDE.md).
