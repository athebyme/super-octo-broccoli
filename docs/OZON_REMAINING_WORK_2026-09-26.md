# Ozon: что осталось до полного запуска

**Состояние 26.09.2026:** волна read-синхронизаций, Vue review и исправления ожидания фото принята на runtime `d7d3f54d…`, healthy без перезапусков. Exact-runtime browser прошёл 72 проверки / 344 раскладки; production подтвердил локальное фото ID 57 после cache pending 202→200, общий и bulk UI, сохранность двух прежних completed jobs и восьми protected групп. Эта доска **не объявляет полный запуск Ozon**: принятые read/UI контуры не заменяют перечисленные ниже live-действия. После сообщения владельца о полном доступе `/v1/roles` подтвердил 11 exact grants для загрузки карточек; это не фактическая публикация и не проверка buyer/inbox, прежние 403 остаются историческими наблюдениями. [Отчёт волны](operations/2026-09-26-ozon-resumable-reads-and-vue-review.md), [полный план](OZON_LAUNCH_READINESS_PLAN_2026-09-24.md), [E2E-чеклист](OZON_E2E_RELEASE_CHECKLIST_2026-09-24.md).

**Текущий приоритет владельца:** [полноценная загрузка и обновление карточек](OZON_CARD_UPLOAD_PLAN_2026-09-26.md). Подготовка, просмотр и отправка конкретных версий должны пройти полный сценарий; подробный план и найденные дефекты ведутся отдельно.

## P0 — данные и действия продавца

**Покупательская цена и скидка Ozon.** Цена продавца и его акции уже разделены в UI. `/v1/product/prices/details` ранее вернул 403 обоим ключам; наличие метода в роли не объясняло отказ. После расширения прав выполнен новый roles-check; доступ именно к prices/details ещё не перепроверен.

- Дальше: точечно проверить новые условия доступа через общий ledger без retry, затем подтвердить семантику полей официальным контрактом; [проект обращения](operations/2026-09-25-ozon-price-access-support-draft.md) подготовлен, но не отправлен. Не подключать платные опции автоматически.
- Готово, когда подтверждённый контракт воплощён в типизированном сохранённом наблюдении покупательской цены и субсидии/скидки Ozon с источником, валютой и freshness; общий UI показывает факты и честное unknown при их отсутствии. Несколько реальных ценовых примеров проверены end-to-end от read до отображения. Один успешный read сам по себе этот пункт не закрывает.

**Отзывы, вопросы и ответы.** Vue inbox и durable очередь проверены offline; текущий кабинет ранее получил 403 на чтение. Заявленный полный доступ ключа ещё не доказал новый ответ этих методов.

- Дальше: точечно проверить нынешний доступ и реальные страницы через штатный ledger, затем отдельно рассмотреть контракт ответа.
- Готово, когда есть авторизованный read собственных фактов и один reviewed reply с конечным readback. Повторять те же 403 без новых условий не нужно. [Граница](operations/2026-09-26-ozon-inbox-durable-refresh.md).

**Создание и обновление карточки.** Synthetic create/update, signed media и защита неизвестного исхода проверены. Старый `uncertain` не превращён в success.

- Дальше: получить подтверждённые габариты, юридические классификации и остальные обязательные исходные факты, выбрать товар для разрешённого pilot; отдельно сверить старую операцию чтением без повторной записи.
- Готово, когда точные create и update пройдут UI → durable operation → provider → readback, а исход старого `uncertain` подтверждён либо честно остаётся неизвестным. [Чеклист](OZON_E2E_RELEASE_CHECKLIST_2026-09-24.md).

**Реальное изменение FBS-остатка.** Чтение складов и exact listing FBS завершилось; stock proposal №3 всё ещё pending без operation.

- Дальше: согласовать товар, склад и количество, получить отдельное разрешение на write pilot, проверить live before-state и guardrails.
- Готово, когда одно явно рассмотренное изменение **фактически изменит количество** на выбранном складе и точный provider readback подтвердит новое значение. Зафиксированный отказ без записи доказывает только negative path; успешное чтение склада также не закрывает stock-write пилот.

## P1 — сверка и эксплуатационная зрелость

**Финансы.** 29 закрытых дней и 70 начислений сверены с повторным API read; `/v1/finance/accrual/postings` дважды вернул 429.

- Дальше: дождаться обещанного владельцем независимого отчёта за сопоставимые период, валюту и часовой пояс. К postings вернуться после новой информации о доступе или паузе.
- Внешняя сверка закрывается, когда независимый отчёт объясняет суммы и корректировки за сопоставимый период. Доступ/контракт postings остаётся **отдельным открытым пунктом** до подтверждённого ответа и сверки; сохранённый 429 не считается его выполнением. [Данные](operations/2026-09-26-ozon-finance-comparison.md).

**Сборка, отгрузка и этикетки.** Заказы, возвраты и отмены доступны read-only; физические ship/label действия не проверены.

- Дальше: получить актуальные официальные схемы и ограничения FBS package/ship/label, сделать typed proposal/reconciliation и synthetic E2E до живого действия.
- Готово, когда один отдельно рассмотренный заказ имеет проверенную принадлежность этикетки и конечный provider readback. [Контракт](design/ozon-fulfillment-write-contracts.md).

**Hosted CI и пользовательский пилот.** Локальный runner и browser matrix повторяемы; hosted GitHub workflow подготовлен, branch gate ещё не подтверждён.

- Дальше: подключить hosted gate, провести сценарии с пятью пользователями, затем наблюдать согласованный семидневный пилот.
- Готово, когда есть green hosted run на точном source/image, разобранные замечания пользователей и семь дней записанных freshness/error/operation наблюдений.

## Отложено владельцем

**Внешнее восстановление.** Локальный SQLite backup реально восстановлен с hash и `quick_check`; последний snapshot проверен за 729.939 s.

- Дальше: вернуться к off-host копии и отдельному восстановлению ключа/media, когда владелец возобновит пакет.
- Готово, когда restore из внешней копии проверен и RPO/RTO измерены. Локальный архив не является off-host recovery. [Evidence](operations/2026-09-26-ozon-resumable-reads-and-vue-review.md).

**Эксплуатационное наблюдение:** прошлый startup достиг healthy примерно через 11,5 минуты после recreate без restart; для нового локального архива потребовалось освободить восстанавливаемый photo cache и проверить свободное место. В следующей приёмке достаточно зафиксировать фактическое время startup и запас диска после backup/фото. Это наблюдение само по себе не означает новый инцидент или изменение обещанного объёма.
