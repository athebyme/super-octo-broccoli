# Цены и остатки Ozon

Экран рабочего решения: фотография и название товара, наблюдённое значение, предлагаемое значение, решение продавца. Существующая «Тёплая редакция» обязательна для цельности Seller Hub: фон #faf9f7, поверхность #ffffff, текст #1a1a1a, граница #e8e5e1, действие #c45d3e, подтверждённый результат #2e7d54. В тёмной теме — соответствующие общие tokens. Inter для работы с данными; display font только у заголовка страницы.

Композиция выровнена влево: заголовок и «Изменить цену или остаток», кабинет/фильтры, список товарных строк. В строке фото, название, сравнение и статус; на мобильном сравнение переходит под название. Создание и групповое подтверждение — native dialog с фокусом и возвратом к исходной кнопке. Деталь — крупное сравнение, точный склад/кабинет, неизменяемые ограничения и решение рядом; на mobile одна колонка.

После критики плана исключены три декоративные step-карточки, технические флаги, повторяющие название карточек числовые KPI и ссылка на формулу WB. Иллюстрация используется только в содержательном пустом состоянии, в списке — реальные фотографии товаров. Слово «сейчас» заменено датой наблюдения: сохранённый снимок не выдаётся за live read. Buyer/promo price никогда не подставляется в поле цены продавца; FBO-сумма не подставляется в поле доступного FBS остатка.


После live price pilot 24.09 подготовка цены явно округляет ввод до ближайшего целого рубля (50 копеек вверх); это политика Seller Hub, не предположение об общем алгоритме Ozon. Под полем появляется ожидаемая сумма, отдельный review сохраняет исходный ввод и выделяет подтверждаемую цену. Та же информация видна в frozen batch и classic fallback. На этапе отправки округления нет. Исторический fractional pending review нельзя автоматически пересчитать: он закрывается без отправки, затем создаётся новое сравнение. Ошибка после принятого provider write отличается по тексту от drift до отправки; новое решение начинается со свежего чтения, без повторного approve старой операции.
