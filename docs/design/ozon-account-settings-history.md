## Проверенные разрывы

`save_ozon_account` блокирует название и default VAT при любой pending/uncertain карточке, media operation или commercial/content proposal. В рабочем кабинете такая история уже есть, поэтому обычные настройки фактически недоступны. Метод также принудительно активирует аккаунт и может выбрать default — эти побочные действия не подходят для безопасного сохранения пары полей. Старый публичный settings POST не требует просмотренной версии. Смена ключа защищена версией, но отдельного журнала акторов/событий нет. Default selection меняет несколько accounts без общего account lock и не увеличивает version снятого default.

## План реализации

1. **Отдельное изменение label/default VAT.** Existing account POST принимает только exact Client-Id, label, optional default_vat и обязательный positive expected_version. Под существующим account lock перечитываются owner/identity/version; меняются только два разрешённых поля и version. Не активировать disconnected, не менять ключ/credential version/default/capabilities/check time/expiry, не создавать job и не вызывать provider. Название доступно при durable uncertain; занятый physical lock возвращает busy. Default VAT относится только к будущим черновикам: existing drafts/proposals/operations и их snapshots не обновляются. Неизвестный VAT не превращать в ноль; явный пустой выбор снимает default только для будущих карточек. No-op не создаёт фиктивное событие/новую версию.
2. **Append-only account journal.** Additive `marketplace_account_events`: seller/account/marketplace, actor user (nullable only for known internal/legacy caller), allowlisted action, observed before/after account/credential versions, whitelisted change facts, UTC timestamp. Успешное локальное изменение и event коммитятся вместе; failure/conflict/busy не оставляет события успеха. Не писать API key, encrypted secret, key fingerprint, raw provider bodies, error response или buyer data. Не создавать задним числом выдуманные события для старых accounts. Прочтение/перезапуск не пишет journal; GET не вызывает Ozon. История начинается с этого выпуска.
3. **Записываемые действия и locks.** Новое подключение, замена ключа, настройки, default selection, disconnect; для публичных POST actor только authenticated current_user, чужой actor отклоняется сервисом. Key replacement сохраняет уже принятые version/account gates. Default fan-out и disconnect replacement должны атомарно учитывать все затрагиваемые accounts: seller-level fail-fast lock, затем sorted bounded account locks (до существующего cap); вторая вкладка не меняет просмотренное состояние бесшумно. Все реальные изменения получают версии и отдельные exact-account events; default selection/disconnect остаются самостоятельными подтверждаемыми действиями. Нельзя ослаблять gates удаления ключа при attempted writes. Внутренние callers без actor помечаются как «инициатор не записан», а не приписываются владельцу.
4. **История в Vue.** Внутри конкретного магазина раскрываемый раздел с компактными строками «что изменилось / когда / кто» и читаемым before→after для названия/ставки/default. Key event сообщает лишь факт замены и необходимость отдельной проверки доступа. Серверный GET owner-scoped, keyset pagination по event ID, максимум 30+1 строк, без общей выгрузки аккаунтов/секретов. Empty — «История начнётся со следующего изменения»; loading/error/retry/load more. GET не пишет отметки прочтения, не вызывает provider/LLM. Late/foreign response не заменяет видимый список.
5. **Конфликт и потерянный ответ.** Viewed version у формы настроек статична и не обновляется background polling. После 409 явный GET показывает текущие сохранённые значения, сохраняет ввод, а обновление viewed version требует явного review и отдельного Save. Контекст ошибки различает настройки и ключ: перечитывание одной формы не даёт согласие другой. Timeout не объявляет отмену и не вызывает automatic retry; readback/optimistic version защищают от двойного события. Навигация/успешное сохранение не теряют focus и понятно сообщают результат.
6. **Проверки.** Pending/uncertain + settings; unchanged crypto/expiry/flags/drafts/proposals/operation attempts, disconnected state, actor/tenant/unknown fields, strict versions, no-op, collision two tabs, physical lock, default fan-out, deletion gates, atomic rollback audit+account, secret-free history, keyset pagination/foreign rows, migration fresh/historical/repeat/interrupted. Real Flask/CSRF/Vue: settings save/history, stale name+VAT, retained input, lost POST/readback, 401/foreign response, keyboard, 320/390/768/1440, both themes/200% reflow. Контракты НДС не расширяются сверх уже поддерживаемого enum; налоговые рекомендации не даются.

## Визуальное решение и критика

Используется `frontend-design`, с соблюдением существующей темы проекта: surface #ffffff, background #faf9f7, text #1a1a1a, muted #6b6b6b, accent #c45d3e, border #e5e1dc; dark/semantic colors наследуются из tokens. Body font форм и serif заголовка страницы сохраняются. Выравнивание слева, readable rows до ~80 символов, icon clock/key/settings только для значения действия. Новая палитра, hero, декоративные изображения и отдельная большая dashboard-карточка для журнала не нужны.

Композиция: существующая форма → понятное сохранённое состояние/конфликт → раскрываемая история этого магазина. Сравнение stale state использует небольшой definition list с текущими значениями; это место принятия решения, поэтому здесь допустима явная структурная рамка. На телефоне значения идут вертикально; desktop остаётся компактным. История не должна вытеснять основное действие или выглядеть как лента технических логов. Secret/version internals не становятся основным пользовательским текстом. Focus и сообщения live-region проверяются в браузере.

Критика: название и VAT можно менять безопасно только если они не активируют аккаунт и не переписывают уже подготовленные карточки. Новый audit не должен становиться фиктивным доказательством старых событий или выдавать сохранение ключа за успешный доступ в Ozon. Одного UI-конфликта недостаточно: серверные version/lock/atomic audit обязательны. Этот пакет не закрывает operator quarantine для недоказуемых provider outcomes — ему нужен отдельный контракт по scope и всем write boundaries, не ручная смена статуса.

### Реализованные уточнения

`credential_version` — версия формата encryption envelope, поэтому при обычной замене ключа остаётся прежней. Для конкуренции используется возрастающая `account.version`. Settings/key conflict states независимы. Mutation services отклоняют caller-owned dirty/flushed transaction до ORM queries; rollback не должен терять чужое незавершённое изменение. Журнал не разбирает сохранённый JSON больше 8 KiB и выводит только четыре allowlisted поля.
