# Ozon: рабочий список качества карточек

## Задача и план

Следующий участок W6/W7/W8: действующий экран качества использует Alpine, не показывает фото, теряет фильтры/выбор и выдаёт JSON вместо объяснимых метрик. GET списка при отсутствии оценок и GET детали вызывают запись пересчёта; общий пересчёт зависит от браузерного цикла, который останавливается после 10 000 товаров и всё равно сообщает успех. Оценка Seller Hub не должна восприниматься как официальная оценка Ozon или разрешение публикации.

1. Убрать пересчёт из GET. Сохранить scoped legacy JSON и явный bounded POST для совместимости; новый workspace читает все доступные активные карточки, включая ещё не оценённые. Scope проверяется до ORM relationships; ссылки и фото разрешаются только для exact seller/account/listing. Локальные оценки не разрешают marketplace writes.
2. Добавить отдельную durable заявку `BackgroundJob(ozon_quality_recompute)`: HTTP только ставит/дедуплицирует, singleton scheduler каждые 10 секунд обрабатывает один exact-account batch до 200 listing IDs. Cursor по ID с верхней границей на момент начала не смещается при удалении/архивации; новые товары после этой границы оценивает обычный scheduler или следующая заявка. Обработано и исходный размер — разные наблюдения, не обещание immutable каталога.
3. Пересчёт локальный: никакого Ozon/image/LLM I/O, decrypt или записи price/stock/drafts. Job claim и все вычисления quality сериализуются process-shared locks. Оставленный running job возобновляется только после захвата lock; crash между записью оценок и checkpoint допускает повтор чистого локального расчёта, не внешней операции. Deadline заявки 24 часа; явная ошибка сохраняет уже пересчитанное. Generic job-status не завершает её по старому timeout и не выдаёт private cursor.
4. Read presentation: фото, название, артикул, последняя наблюдённая оценка/дата, причины, понятный приоритет исправления; unassessed и изменившийся после оценки каталог обозначаются отдельно. Среднее не выдаётся за актуальную официальную оценку. Локальные метрики имеют подписи и источник; unknown не превращается в 0. Причины дают переход к карточке/подготовке/аналитике, без JSON/ручного ввода ID.
5. Vue 3: фильтры, поиск, сортировка, страница и detail в URL; back/reload и modified clicks работают. Выбор exact IDs сохраняется между страницами до смены выборки и переносится в существующий typed AI context без LLM вызова. Native dialog/Escape/focus, запросы с 10s timeout/abort/revision/exact scope guard, network/session/empty/partial states сохраняют данные. Фоновая заявка переживает закрытие вкладки; polling только на видимой странице, потерянный POST запрещает повтор до GET состояния.
6. Проверки: tenant/CSRF/strict query, GET без записей, unassessed/stale/unknown/zero, pagination/Unicode search, budget failures; queue dedup/restart/archive/new IDs/races/lock/expiry/flag; Vue late response/timeout/session/selection/URL; настоящий Chromium, две темы, 1440/768/390/320, фото и клавиатура. Стенд → backup preflight → deploy → проверка production без marketplace writes.

## Дизайн до реализации

Сохраняется заданная тема «Тёплая редакция»: фон #faf9f7, surface #ffffff, текст #1a1a1a, вторичный #6b6b6b, accent #c45d3e, контрастный accent #a34a2f; dark наследует существующие tokens. Inter — рабочие строки/цифры; Instrument Serif — заголовок. Используются реальные фото товара и существующие SVG icons; декоративная генерация здесь не помогает различать карточки.

Композиция слева направо: фото и идентичность товара → последняя оценка → 1–3 понятные причины → явное действие. На mobile каждая строка складывается в блок с сохранённой иерархией, без горизонтального табличного скролла. Над списком — компактная сводка покрытия оценками, форма поиска/фильтров и статус фонового пересчёта. Деталь объясняет составляющие, дату оценки и следующий шаг; служебные IDs не составляют основной интерфейс.

Критика: четыре одинаковые KPI-плитки и абстрактное «Влияние: 42» не помогают исправить товар. Вместо них — покрытие и рабочая очередь с явным смыслом локального приоритета. Общая тема закреплена владельцем; отдельная палитра и новые шрифты не вводятся. Проверка доступности следует [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md): semantic controls, label/focus, размеры фото, URL state и сохранение данных при ошибках.
