# Ozon: история и сравнение финансовых загрузок

## Задача и план

W10 требует расследуемых расхождений, истории периода и проверки поздних изменений. В БД сохраняются завершённые immutable snapshots, но UI даёт только текущий закреплённый журнал. Новый read-only экран открывает историю и сравнивает две конкретные загрузки. Это сравнение сохранённых наблюдений API, не бухгалтерская сверка с отчётом Ozon и не доказательство причины изменения.

1. История: exact seller/marketplace/account, только completed/current-contract snapshots, до 16 + явный truncation. Даты загрузки и её период видны до выбора. Чужой/удалённый pin — ошибка без latest fallback.
2. Сравнение: два разных явно выбранных snapshot, порядок по completed_at/id; только пересечение полностью загруженных календарных дней. Непересекающиеся периоды отклоняются. Никакой пропавший край rolling window не становится удалённым начислением.
3. Идентичность сравнения — exact provider accrual_id внутри того же кабинета. Сравниваются наблюдённые top-level сумма/валюта/дата/категория/номер и нормализованный состав SKU/компонентов. Порядок child rows, current type_name и локальные listing/posting связи не являются изменением финансового факта. Added/missing/changed — различия наблюдений, не автоматические «возврат/отмена/корректировка».
4. Итоги независимо складываются Decimal только из top-level total_amount; old/new/delta отдельно по валютам. Nested fee explanatory, не второй расход. Нулевая сумма допустима; отсутствие строки не изображается наблюдённым нулём. No P&L/buyer price inference.
5. Бюджеты: 10 000 фактов на snapshot, 100 000 child rows суммарно, 16 MiB текста, SQL progress deadline 5s/busy timeout 200ms; один consistent SQLite read snapshot, cleanup до возврата pool. Превышение — явный отказ без частичного сравнения. API не вызывает provider/LLM и не создаёт jobs/записи.
6. Vue: отдельная страница, вход из финансов; выбранная пара, filter и page в URL. До/после, summary по валютам, список различий и exact snapshot ссылки в существующий detail. Loading/error/empty/pruned/foreign/no-overlap, abort/revision/10s timeout и сохранение предыдущего результата с явной подписью. Никакого silent compare после смены выбранной пары.
7. Проверки: Decimal/currency/zero, changing components/order, common dates, partial/foreign/retention races, budgets, GET-only, late responses, themes/mobile/keyboard; production local comparison + сохранность каталога/цен. Деплой принятого образа, полный startup guard.

## Дизайн

Экран остаётся частью «Тёплой редакции»: фон #faf9f7, surface #fff, text #1a1a1a, secondary #6b6b6b, accent #c45d3e и contrast accent #a34a2f; dark наследует theme tokens. Inter для сумм/форм, Instrument Serif только заголовок. Иконки существующего registry, без новых иллюстраций.

Композиция: заголовок и ссылка назад → две подписанные загрузки «Раньше / Позже» + явная кнопка сравнения → общий период и смысл сравнения → old/new/delta по каждой валюте → фильтры различий и компактные строки начислений. Desktop суммы выровнены справа, на мобильном before/after располагаются под ID. Фокус видим, цвет подкреплён словами; нулевая разница не становится общим «всё сверено».

Критика: универсальная панель KPI или красные «потери» для missing records приписала бы данным непроверенный смысл. Используются спокойные сравнительные строки и формулировки наблюдений. Первичный сценарий — найти изменившийся факт и открыть обе версии, а не оценивать прибыль.

## Открытые условия W10

Нет самостоятельного документа Ozon Seller за репрезентативный период: внешняя бухгалтерская сверка и её методика остаются открытыми. До перехода календарного окна исследован snapshot с 71 top-level фактом, включая наблюдённые компоненты возвратной логистики, а актуальная API-сверка 26.09 подтвердила 70 начислений за 29 закрытых дней; type label сам по себе не доказывает полноценный accounting cycle. Новый UI не закрывает этот gate и не инициирует создание provider reports.

## Проверка реализации

Тесты подтвердили целостность сравнения при удалении newer snapshot параллельным writer в WAL: начатое чтение получает обе исходные версии, следующий запрос возвращает 404. Проверены смена валюты, настоящий ноль, изменение только компонентов, перестановка SKU/услуг и новые current labels без ложного финансового изменения. В старых finance UI fixtures восстановлены фактические `account_id/domain/period`, обязательные после ранее выпущенного общего refresh scope guard; guard не ослаблен.

Браузерный осмотр: сохранена существующая тема; суммы по валютам читаются отдельно, mobile складывает before/after по вертикали. Под каждым выбранным snapshot видны его календарные даты ещё до сравнения; отсутствие подходящей ранней версии имеет явный следующий шаг. Кнопка сравнения выровнена с полями, product copy не требует понимания API.

Реализация развёрнута и принята: [release evidence](../operations/2026-09-26-ozon-finance-comparison.md). API по отправлениям получил два 429 после соблюдения cooldown; внешний бухгалтерский отчёт владелец предоставит позже. Эти ограничения не закрыты сравнением локальных snapshots.
