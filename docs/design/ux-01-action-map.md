# UX-01: карта действий «было → станет → где действие»

Дата: 30.09.2026. Статус: карта принята для реализации; итоговые проверки и ограничения — в [отчёте](ux-01-implementation.md). Существующие маршруты сохраняются.

Основание: фактические ссылки seller-навигации и command palette в `templates/base.html`, существующие routes и UX-handoff. В первом столбце сохраняются текущие endpoints: при внедрении они остаются доступны по своим URL. Новый пункт меню не означает новую модель данных или универсальный backend.

## Термины и границы

| Объект | Что означает | Что показываем рядом |
| --- | --- | --- |
| Товар поставщика | Исходная строка каталога поставщика (`SupplierProduct`) | Поставщик, исходный артикул, наблюдённые факты |
| Внутренний товар | Seller-owned импортированная строка внутреннего каталога (`ImportedProduct`), связанная с источником и опционально WB; не Ozon-черновик и не универсальная master-модель | Внутренний ID и источник; возможная связь с WB; термин проверяем перед внедрением |
| Карточка WB | Опубликованная WB-проекция `Product` с настоящим nmID | WB, nmID, продавец; не переименовываем её в универсальный master product |
| Карточка маркетплейса | Listing конкретного кабинета, в частности Ozon `MarketplaceListing` | Канал, кабинет, offer/product identity |
| Черновик Ozon | Версия подготовленного состава для конкретного кабинета (`MarketplaceProductDraft`) | Источник, кабинет, версия, требования категории |
| Предложение изменения | Просмотренные новые значения цены/остатка | Наблюдённый снимок при создании и предлагаемые значения, валюта, склад при необходимости |
| Операция | Зафиксированная попытка действия и её наблюдённый результат | Тип, канал/кабинет, состояние отправки и сверки отдельно |

WB-объединение по imtID — инструмент WB, а ручная связь внутреннего товара с Ozon listing — отдельное действие. Склад выбирается в контексте конкретной FBS-задачи и не становится общим переключателем для всех каналов.

Seller-навигация не расширяет к ним доступ. Command palette обновляется вместе с меню и сохраняет поиск полезных прямых действий.

## Действия внутри рабочих областей

| Было | Станет | Совместимость и защитные проверки |
| --- | --- | --- |
| Vue detail `/marketplaces/listings/view/<id>` и classic `/marketplaces/listings/<id>` | Общий заголовок, режимы «Обзор / Управление», одинаковое имя объекта и контекст | Старые URL открывают свой режим; seller/account/link versions и FBS warehouse guards сохраняются |
| Возврат «Каталог» с карточки | «Назад к найденным карточкам» с сохранённым разрешённым внутренним URL | Внешние, protocol-relative и неразрешённые маршруты отклоняются; прямой вход имеет безопасный fallback |
| Технические JSON в основных блоках detail | «Диагностика» через раскрытие, а конкретная ошибка и следующий шаг — перед деталями | Raw snapshot не удаляется и не попадает в URL/общую рассылку |
| Импорт, черновик, source batch и результат на разрозненных экранах | Последовательность подготовки над существующим потоком | Сохранение локально не вызывает publication; fresh review точных версий и отдельное подтверждение остаются |
| Смена категории и AI-предложения | Действия в полях подготовки, с существующим category review / evidence | Dirty ввод сохраняется, версия/source drift блокируют apply; AI не становится исходным фактом |
| Предложение цены/остатка рядом с current facts | Отдельная область «Предлагается» с переходом к review | Валюта, exact account/warehouse и версия указаны; unknown buyer price не подменяется seller price |
| Окончание batch как «Завершено» | Общий результат и счётчики: успех / частично / завершено с ошибками | Статус выполнения backend не переписывается; неизвестный исход не считается ошибкой с безопасным retry |
| WB quality, beta quality, фотографии источника, Image Lab | «Товары → Качество / Медиа», contextual tools | WB-only действия помечены; локальный artifact и Ozon media publication различаются |

## Критерий полноты карты

Перед каждым переносом проверяется не только наличие пункта меню: исходные массовые действия, фильтры, detail routes, exports, review, диагностика и разрешённое восстановление должны быть перечислены в scoped change manifest. Эта карта покрывает обнаруженные входы общей навигации; она не заменяет инвентаризацию всех кнопок внутри каждого экрана. Необнаруженное действие до переноса считается незавершённой проверкой UX-01.11.

## Реализованные контекстные входы

| Код | Новое место прежних действий | Реализация |
| --- | --- | --- |
| .2/.5 | Общий header карточки: каталог, обзор, управление; диагностическое раскрытие | Listing workspace partials и safe return helper |
| .6 | Текущий этап/следующее действие; полный путь в «Показать все этапы» | Preparation journey на исходных source/internal/draft/review/result URLs |
| .7 | «Истории по каналу» в исходных WB/Ozon histories | Native history nav; detail/revert/quarantine остаются на прежних экранах |
| .8 | «Качество и медиа» рядом с текущим инструментом | Classic/beta WB, quality Ozon и Image Lab с явной областью |
| .9 | «Цены, расчёты и история» внутри исходных price/proposal screens | Current WB, расчёт, история, защита, формула, мониторинг, Ozon proposals |
| .10 | «Разделы настроек»: подключения/товары/уведомления/диагностика | Shared settings nav; exact account health внутри подключения |

Канал, кабинет, права, fresh review и прямые ссылки проверяются отдельно от наличия пункта. Наблюдённые фотографии источника остаются в supplier detail; изменения медиа открываются в соответствующем инструменте, без нового универсального media engine.

## Дополнение кандидата от 01.10.2026

Это карта принятого кода, а не заявление о deployment. Точный статус проверок: [приёмка продолжения](../operations/2026-10-01-ozon-ux-acceptance.md).

| Исходное действие / пробел | Место в кандидате | Охват и эффект |
| --- | --- | --- |
| Общий контент внутреннего товара доступен в моделях, без явного bounded редактора | Classic/beta «Мои товары» → «Общий контент» → `/my-products/common-content?product_id=…` | Одна карточка или exact набор до 50; title/description/известные фото/именованные характеристики; preview и save только общего товара |
| Ручные значения трудно отличить от обновлений источника и AI | Поля общего редактора: итоговое/наследуемое/переопределённое, явное «Наследовать» | Сохранение не перепривязывает товар и не применяет его в каналы; существующие draft/review формы остаются отдельными |
| WB выбор терялся при смене страницы | `/products` → выбор страницы/всех отфильтрованных/исключения → массовый редактор | Exact подписанный набор до 200 по внутреннему лимиту; фильтр/аккаунт не расширяют выбор молча, весь каталог не загружается в браузер |
| WB ручная массовая правка нуждалась в точном охвате до записи | Массовый редактор → предпросмотр → отдельное подтверждение | Selected/eligible/changed/skipped/errors, exact diff; свежая проверка и одноразовый claim до provider I/O |
| В WB single edit не было выбора недостающих допустимых характеристик | `/products/<id>/edit` → добавить поле из exact subject schema | Общие dictionaries/types/grams/multiple с bulk; sizes/SKU остаются read-only |
| Готовый Ozon draft со своим VAT блокировался отсутствием account default | Список черновиков и просмотренная загрузка | Готовность определяется VAT самой карточки; default служит новым черновикам, остальные safety gates сохранены |

Возвраты WB используют разрешённый `/products` URL с поддерживаемым поиском/сортировкой/страницей. Channel refs общего редактора — контекст сравнения, не скрытый список публикации. Состояния pending/unknown/409 показывают необходимость чтения и нового review; переход к исправлению не отправляет товар.
