# Ozon seller draft AI completion: minimal implementation contract (implementation, 2026-09-27)

Status: implementation contract; not yet deployed. The owner has requested real parsing of incomplete products; a bounded AI pilot follows offline acceptance. This contract does not itself authorize an Ozon publication. `source_prepare`, manual draft editing, and `reviewed_drafts` publishing remain usable independently. This is a separate seller-owned proposal workflow; neither `MarketplaceOperation`, `ReplyDraft`, nor `CommercialProposal` stores its AI state.

## Exact input and provenance

Acceptance requires seller, active owned Ozon account, 1–200 exact owned draft IDs with a complete positive expected-version map, `confirm_generate=true`, and 24–128 character random `request_key`. Draft must have a seller-selected `product_type_id` and fresh category/type/attribute/dictionary references. It does not require the Ozon publication flag or a connected Ozon key. It requires an explicitly configured native DeepSeek parsing profile and an available local AI budget. Credentials follow existing `AIConfig.for_seller`: configured central profile first, otherwise the exact seller profile; a nonnative chosen provider/base is rejected, never silently switched with its key. Task-specific model remains Flash. Canonical fingerprint covers seller/account, ordered draft IDs and versions, model/profile version; the same key and fingerprint returns the same run, a changed body returns 409. A second active item for one exact seller/account/draft is deduplicated or rejected before an LLM attempt, even with a different request key.

Use only a bounded whitelist from the whole `ImportedProduct.original_data` snapshot actually reviewed by the seller. Fall back to the whole `SupplierProduct.original_data_json` snapshot only when the imported snapshot is absent and the exact `ImportedProduct.supplier_product_id` FK resolves; record which whole snapshot was chosen and never silently switch to fresher supplier data. Never merge per-field fallbacks from normalized `ImportedProduct` columns, `ai_*`, `marketplace_fields_json`, `unverified_suggestions`, other sellers, or draft values. For the first seller lane, allow identity title/description/brand/category and explicit source characteristics/material/color/size text; remove price, cost, stock, barcodes, media URLs, credentials, customer data, and free-form instructions. Require a source snapshot; absent snapshot means manual entry. Source dimensions and compliance facts must not be guessed. The source-only SHA256 includes source identity and whitelisted facts but excludes generated suggestions. Filled draft attributes/complex groups are sent only as bounded non-overwrite constraints. Each item seals exact draft version, imported product ID, selected category/type, source SHA256, type/schema SHA256, every relevant dictionary SHA256, and filled-slot fingerprint before any physical call.

`MarketplaceFactPackBuilder.build` cannot be used wholesale as LLM evidence because it includes seller-current normalized values; the source snapshot extractor in `supplier_luna_enrichment.py` and evidence helpers in `scripts/validate_luna_parsing.py` are useful patterns, with a new seller-specific whitelist and exact FK check. Existing `MarketplaceDraftService._normalize_attribute_items`, `_normalize_complex_attributes`, `_validate_attributes`, `_build_validation_result`, and `OzonReferenceService.reference_is_fresh/dictionary_is_fresh` remain native gates, not optional model scores.

## Durable storage (new migration, no legacy rewrite)

`OzonDraftCompletionRun`: id/uid, seller_id/account_id/actor_id, BackgroundJob ID (public UID), request_key_hash + canonical input fingerprint unique per seller, profile/model IDs, status `pending|running|cancelling|completed|cancelled|failed`, next_due_at, lease token/until, requested/max physical calls and nullable aggregate usage counters, created/updated/completed timestamps. Initial max physical calls per run is `min(80, ceil(item_count / 6) * 2 + 4)`; this is a lifetime cap, not a retry allowance. Seller/account FKs restrict audit deletion; no raw prompt/response or API key. Index `(status,next_due_at,id)` and seller/account history. A request-key readback endpoint prevents lost-POST resubmission. Flag disable blocks generation/apply but leaves owned readback, audit and cancellation available.

`OzonDraftCompletionItem`: run_id, ordinal, seller_id/account_id/draft_id and immutable imported product/type IDs, expected draft version, sealed source/schema/dictionary/filled-slot hashes, state `pending|reserved|unknown_response|proposed|no_evidence|stale|needs_input|failed|cancelled`, next_due_at, attempt count, exact `call_id`, safe code, nullable usage, timestamps. Unique `(run_id,ordinal)` and `(run_id,draft_id)`; partial unique active `(seller_id,account_id,draft_id)` prevents duplicate concurrent model calls across request keys. A chunk groups <=6 items of one exact compatible type/schema/dictionary, with one shared physical call record.

`OzonDraftCompletionSuggestion`: item_id, exact external attribute ID + complex ID/group ordinal, canonical typed values JSON (bounded native shape), evidence JSON pointers/literal quotes (bounded), deterministic provenance code, status `proposed|accepted|rejected|stale`, reviewer ID, reviewed/applied draft version, timestamps. Unique exact slot/group identity per item. The first accepted lane handles simple string/dictionary attributes only. Complex groups are excluded from prompts and rejected by validation/apply with `complex_group_requires_manual_review`; extending them requires native validation of every repeated group before enabling grouped acceptance. Never store provider raw text, secrets, prices, stock, barcodes, media, or arbitrary model explanation. A fourth shared `AIParsingAttempt`/ledger records physical reservation, `call_id`, lane, model, seller, request fingerprint, start/finish/deadline, known HTTP status/retry due, nullable prompt/completion/cache-hit/cache-miss/reasoning tokens and nullable provider/estimated cost separately. This ledger is shared with admin Flash parsing; merely adding a seller-only semaphore would not satisfy the shared budget. Admission caps are 2 active runs/seller, 20 active runs globally, and 200,000 retained suggestions globally; capacity rejects new admission with typed `ai_capacity_full` rather than silently purging audit.

`OzonDraftCompletionReview` is a fifth, append-only local audit table for an apply/reject command: seller/account/draft/actor, unique seller-scoped request-key hash, exact request fingerprint, action, version before/after, bounded exact suggestion ID list and timestamp. Review command, suggestion states and draft mutation commit together. A lost apply response is read/replayed against this command rather than applying a new version twice. It is not a marketplace operation.

## HTTP and worker

`POST /marketplaces/api/drafts/ai-completions` returns 202 `{job_uid,replayed,mode:'draft_suggestions',status}` + Location. `GET /.../by-request` with `X-AI-Request-Key` and exact account scope, `GET /.../<uid>` bounded 200-item summary, `POST /.../<uid>/cancel`, and `GET /drafts/<id>/ai-suggestions` are read-only with respect to Ozon. `POST /drafts/<id>/ai-suggestions/apply` accepts exact selected suggestion IDs, expected draft version and a review key; response includes the recorded version transition and `requires_validation`; the UI reloads the editor and explicitly requires a fresh whole-card validation before publication. Reject missing/duplicate/foreign IDs, unsupported complex slots, and stale/filled slots with typed 409. Rejection of suggestions is a separate reviewer decision, not a draft edit. All POSTs use session, CSRF and seller/account checks; GET refreshes current CSRF after session recovery.

Existing singleton scheduler owns one bounded coordinator tick; no web-request LLM, Ozon read, image, or draft mutation. Tick selects due items fairly by due/last-attempt/id, <=200/run, <=6 same-schema items/call and initially <=3 global/<=2 seller physical calls across admin and seller parsing lanes. Coordinator reserves durable call/usage budget and per-item state before launching ORM-free HTTP futures; futures return bounded parsed response metadata only. First-lane input is capped at 64 KiB and JSON output at 8,000 tokens per physical call. No SQL writer transaction or account lock spans HTTP. Native DeepSeek `deepseek-flash`, `thinking.type=disabled`, JSON output and single transport attempt with a maximum 60-second HTTP timeout via a new task-specific profile; no OpenRouter/native ID mixing or implicit provider/model fallback. Both native admin Flash parsing and seller completion reserve the shared `AIParsingAttempt` ledger and use `ozon_draft_ai_transport.flash_completion` with typed outcomes; the legacy generic `AIService.chat_completion` is not used for these physical calls. A known 429 may reschedule after full Retry-After with a newly reserved budgeted attempt; timeout/lost response/crash after reservation is `unknown_response` and is never auto-replayed. An unacknowledged reservation becomes durably unknown after 120 seconds even if its worker disappears; it never becomes pending by lease expiry. Malformed/ungrounded 200 is terminal for that attempt; repeated prompting must not bypass Python gates. Cancellation prevents new reservations and discards a late result; leases fence every post-HTTP commit. On restart, reserved calls with expired leases become unknown, not pending. Record reported usage or unknown (never zero by default); use separate cost estimate only when price table is known.

Before saving suggestions, re-read exact source/type/schema/dictionaries/draft version and filled slots. A mismatch marks the item `stale`, keeps only safe status/usage metadata, discards the stale model content, and writes no suggestion into the current draft. Validate output JSON with duplicate-key/nonfinite/size checks; exact attribute IDs and complex scope; native type/cardinality/range/unit/dictionary membership; evidence pointer and literal quote using `validate_luna_parsing.pointer/evidence_quotes/value_grounded_in_source`; explicit numeric/measurement boundary rules. Semantic aliases require a closed reviewed rule and provenance marker. No confidence threshold turns inference into observed fact. Unknown composition/country/age/certification/marking/package measurements remains absent/manual. Save only suggestions that pass both grounding and native gates; retain only a safe aggregate rejection code in this first lane, without raw model body. Per-field rejected-slot explanations remain a UX extension; rejected values are not offered for acceptance.

## Apply transaction

Under one short SQLite writer claim, re-read exact seller/account/draft version and immutable item fingerprints, current source-only snapshot, selected type/schema/dictionary hashes, existing attributes/complex groups and active publication. Require each selected slot still missing; merge only selected proposed values into current arrays, preserving every manual/previous value and all commercial/media/dimensions/barcode fields. Run native normalizers + complete attribute/complex validation on the merged shape. Use the internal `MarketplaceDraftService._update_draft_core(commit=False)` flush-only path inside a caller-owned writer transaction, so draft version bump, invalidated publish validation, accepted suggestion states and reviewer audit commit atomically. Do not call current committing `update_draft` and then write suggestion audit in a second transaction. A successful partial apply bumps the draft version; unselected suggestions remain in the audit, require fresh review and revalidation against the new version before any later apply, and are shown clearly as needing revalidation rather than silently discarded or still applicable. An invalid whole-card result can remain a draft with actionable validation errors; missing account credentials/publication flag do not block accepting an otherwise grounded local suggestion. The seller must validate and explicitly submit the new version through `reviewed_drafts`; apply never creates `MarketplaceOperation`.

## Acceptance gates and workstreams

1. Schema + storage: additive tables/constraints/indexes, tenant and audit FK tests, bounded cleanup/capacity. No old run conversion.
2. Source/validator: whole-snapshot whitelist, source-only fingerprint, exact evidence/numeric/dictionary/complex gates, source-injection and AI-self-evidence tests. Reuse Luna validator primitives without importing its admin apply semantics.
3. Shared Flash transport/ledger: native profile, bounded response, typed 429/Retry-After, process-shared 3/2 reservations and nullable usage; instrument both admin and seller physical parsing paths before declaring shared fairness. Pilot <=12 real items only after offline tests, then <=60/<=200 gated waves.
4. Durable seller coordinator + routes: request-key race/readback, same-draft active dedup, 6-item compatible chunks, cancellation/restart/unknown response, fair due selection, no HTTP in request, no provider writes.
5. Apply + UI: exact selected IDs/version, atomic review+draft CAS, typed stale/missing-field errors, keyboard/mobile/dark/light browser coverage; progress separate from publication readiness.

Offline tests must cover 200 selection, source-only versus old AI/normalized drift, tenant/CSRF, same-key lost response and different-body conflict, 21+ fairness, global/seller concurrency and call reservation before HTTP, known 429 full Retry-After, timeout/expired lease no replay, cancellation late result, malformed/duplicate/ungrounded model output, dictionary/type/schema/source drift, manual edit preservation, unsupported complex group rejection, apply transaction crash rollback, and a fake-provider path from local `source_prepare` needs-input through accepted suggestion and fresh reviewed-draft version to one queued operation. A real AI parsing pilot is separate from Ozon publication acceptance.
