# Seller AI UI contract — implementation, not deployed

All routes below require the seller session, enforce exact seller/account ownership and return JSON with `success`, fresh `csrf_token`, and `Cache-Control: private, no-store`. All POSTs require CSRF. No endpoint performs model/provider I/O. UI uses native values as text, never HTML.

- `POST /marketplaces/api/drafts/ai-completions`: JSON `{account_id,draft_ids,expected_versions,confirm_generate:true,request_key}`; IDs are 1–200 exact integer draft IDs, versions map has precisely those string keys. `202 {success:true,run,replayed,csrf_token}`. Run `{job_uid,account_id,mode:'draft_suggestions',status,model,total,physical_calls,max_calls,items,summary,created_at}`; each item `{id,draft_id,expected_version,title,status,code,next_due_at}`. Status never implies publication readiness.
- `GET /marketplaces/api/drafts/ai-completions/by-request?account_id=...`, header `X-AI-Request-Key`: same run envelope; 404 includes fresh CSRF. After an observed 404 an explicit same-key, same-payload retry is safe; no automatic POST or newly generated key.
- `GET /marketplaces/api/drafts/ai-completions/<uid>`: same envelope. Poll only while pending/running/cancelling, on visible tab. `POST /.../<uid>/cancel` stops new reservations; a physical request already sent may still incur usage, and its late suggestions will not be applied.
- `GET /marketplaces/api/drafts/<draft_id>/ai-suggestions` (optional exact integer `item_id`): `{success:true,draft_id,account_id,version,item,suggestions,review_token,code,csrf_token}`. `item` is null or `{id,status,code,expected_version,run_uid}`. `suggestions` includes all statuses from this item, bounded to 200. Each suggestion `{id,attribute_id,complex_id,group_ordinal,values,evidence,provenance_code,status,name,label,applicable}`. IDs in native attribute/complex identity are decimal strings. `values` uses native canonical `[{value:'...', dictionary_value_id:'...'}]` (dictionary ID only if present). `evidence` is `[{path:'/source/key',quote:'literal source text'}]`. Display attribute name, proposed label, evidence, and “Предложено AI”; accepted fields may be shown as “Принято вами”. Unknown values are not displayed as zero. `applicable` means a proposed value can be selected on this exact review. The first lane admits simple attributes only (`complex_id: "0"`); complex groups remain manual. Group-aware UI selection is reserved for a separately validated future extension.
- `POST /marketplaces/api/drafts/<draft_id>/ai-suggestions/apply` and `/reject`: `{suggestion_ids,expected_version,review_token,request_key}`. `200 {success:true,review,csrf_token}`; review `{review_id,draft_id,action,version_before,version_after,suggestion_ids,replayed,requires_validation}`. Reject has `version_after:null`. Store exact pending payload before POST. A repeated exact review key returns the recorded command; never apply twice. After any accepted/rejected response, reload both the current editor and suggestion GET. Partial application bumps version; unchecked suggestions require the new token from a fresh GET. A manual edit or changed source/schema makes old suggestions stale and requires a new generation.

Errors are `{success:false,code,error,csrf_token}`. Display actionable text. 401/login redirect pauses actions; 403 blocks scope; 409 requires fresh review except a pending unknown response, which needs readback/replay of the same key; 429 local admission capacity means wait for earlier runs, not a marketplace error. Unusable source/schema appears as per-item `needs_input` without a model call; other admitted items continue. Generation is optional and ready cards can be sent independently through the normal reviewed publication step.

UI entry: existing Vue draft editor and bounded draft selection. Generation must show exact count/account and explain it only fills empty characteristic slots from source facts; preserve seller/manual values. Keep progress, AI review and Ozon publication separate. Reuse real source product photos and existing icons/theme; no decorative generated product imagery.
