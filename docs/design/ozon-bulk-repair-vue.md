# Ozon: массовое исправление в общем Vue-интерфейсе

## Проблема и последовательность

После последнего принятого выпуска `9d0bf9fd8fe54…` основной repair остаётся большой HTML-формой с отдельным DOM-контроллером. Нет фото, предварительного списка затронутых строк, сохранения ввода после частичного отказа и честного восстановления после потери ответа. Значения разных схем массово заполняются без видимого списка исключений. POST с JSON Accept при успехе всё равно перенаправляется. Бизнес-контракт локального repair, exact scope/version/account lock и отдельная публикация уже существуют.

1. Сохранить классический template/asset как fallback; основной route отдать Vue. Расширить bounded read model: display-only фото исходного seller-owned товара, typed definitions и явное влияние смены типа на сохранённые характеристики. Не добавлять provider/media/LLM I/O в request.
2. Добавить JSON-ответ для существующего form-urlencoded POST и bounded результат каждой из максимум 200 строк. Form parser, 2 MiB budget, seller/account/source/version/schema guards остаются общими; JSON request body по-прежнему не заменяет форму. Ответ отделяет сохранение от готовности отправки, исключение от удаления и row failure от общего успеха.
3. Vue: список с фото и поиском, фильтр/категория/page в URL, выбор exact строк между страницами, форма одной раскрытой карточки и ссылки на индивидуальный редактор составных полей. Переиспользовать typed field/photo components одиночного Vue-редактора; не создавать другие правила Boolean=false, Decimal, коллекций и official dictionary.
4. Массовое заполнение сначала показывает affected count, exact строки/до-после и несовместимые/отсутствующие поля. Dictionary display копируется без чужого ID и заново разрешается сервером в каждой exact schema. Никакого автоматического выбора ТН ВЭД/маркировки или сохранения category mapping. Смена типа подтверждает потерю прежних характеристик и отключает ввод старой схемы до сохранения нового типа.
5. Сохранение имеет review выбранных строк и локальную валидацию ввода. Ошибочные строки сохраняют пользовательский ввод; успешные обновляются из свежего read model. Version conflict показывает сохранённое и введённое. Lost POST/5xx не повторяется автоматически: повторная запись блокируется, состояние читается отдельно, пользователь явно принимает свежую версию/разрешает конфликт перед новой проверенной отправкой. Маркер неизвестного исхода переживает reload, но чувствительный контент в browser storage не пишется. URL не содержит черновой ввод.
6. Unit/API и Node assertions: exact scope, 2 MiB, duplicates/unknown fields, partial row result, conflict, cross-type dictionary, Boolean=false, bulk exceptions, stale search race, session/offline/lost POST. Full-app Chromium с настоящими routes/CSRF/SQLite на network-none: редактирование/повторное открытие, partial/unknown, category impact, responsive/keyboard. Проверить 200 строк с пагинацией; не рендерить тысячи полей одновременно.
7. После проверки точного candidate image: backup/critical env gate, deployment, real GET-only browser/read acceptance, health/scheduler/history. Реальных публикаций, ценовых/складских записей и нового provider pilot этот пакет не выполняет. Весь Ozon launch этим repair-пакетом не объявляется закрытым.

## Визуальный план

Сохраняется заданная тема Seller Hub: chalk `#faf9f7`, paper `#ffffff`, ink `#1a1a1a`, border `#e8e5e1`, action `#c45d3e`, attention `#9a6b1f`; dark берёт существующие theme tokens. Instrument Serif — заголовок раздела, Inter — товары/формы/действия. Акцент служит действию, amber — требованию проверки; ready не объявляет разрешение provider write.

Главный элемент — сами товары с фото, артикулом и конкретной причиной. Форма открывается рядом с выбранной строкой; массовая панель появляется по выбору и показывает число карточек. Без нового hero, декоративных метрик и технических ID в обычных подписи/справочнике. Иконки используют существующие inline SVG/stroke приёмы, фото — cache delivery. Генерация новой иллюстрации здесь не помогает исправлению товара.

```text
Исправление карточек                 К результатам загрузки
магазин · сохранение черновиков
[поиск] [категория] [состояние]             [выбрано N]
☐ фото название / артикул       причина        Изменить
  раскрытая типизированная форма + ошибки и текущие значения
☐ фото название / артикул       причина        Изменить
                 [страницы]
выбрано N    [Заполнить поле…] [Проверить изменения…]
```

На 320 px строка складывается в фото/название и отдельную линию действий, поля — в один столбец. Dialog имеет ограниченную высоту, собственный scroll, Escape/focus return. Обычный текст слева, числа tabular; reduced motion, focus-visible, labelled controls и явные pending/unknown/empty состояния обязательны. Перед кодом план сверён с brief: сохраняет уже выбранную тему, а не вводит вторую визуальную систему; review и фотографии помогают точному выбору, технические объяснения оставлены только у реально рискованных действий.

Ревью интерфейса опирается на [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md); локальные guards и пользовательское поручение определяют разрешения. Статус: реализация и точный кандидат прошли 9 bulk-browser сценариев/64 layouts и общий browser 14/86; production принят 26.09 в 15:43 МСК: 3 партии/13 строк, 6 сценариев/48 layouts, без изменений черновиков/операций. [Отчёт](../operations/2026-09-26-ozon-bulk-repair-vue.md). При восстановлении сессии успешный scoped GET также обновляет CSRF без сброса ввода; завершение входа в новой вкладке и последующее сохранение проверяются настоящими HTTP/CSRF.
