## Что изменил новый Ozon handoff

При первоначальной сверке статус от 30.09 был важнее исторических формулировок июльского мастер-плана и первых сентябрьских аудитов. Он **сообщал** об успешном изолированном прогоне: 12 стадий, 2399 проверок, без failures/errors/skips, и совпадении 1152 файлов с замороженным манифестом. Эти артефакты в UX-работе независимо не перепроверялись; это сведения Ozon-агента, а не новый результат наших тестов. **Обновление перед реализацией:** свежий handoff явно указывает четыре изменившихся файла; прежние 2399 проверок и манифест относятся к предыдущим байтам. Текущая приёмка ведётся отдельно в отчёте реализации. Последующая read-only сверка 30.09 в 14:30 UTC выявила уже шесть отличий от прежнего Ozon-манифеста, в том числе уточнение ценовой семантики. Ни один старый зелёный отчёт не переносится на новый source автоматически.

Новая версия не подтверждена в production. Ещё открыты свежий принятый backup, точная runtime-сборка, репетиция миграций, реальные Flash/create/update/readback и проверка эквивалентности фото после возможной замены URL на CDN. Исторический образ `d7d3f54d…` — последнее наблюдение в handoff, не проверка его текущего состояния. Ограничения host-доступа в том отчёте относятся к среде другого агента; они не проверялись заново и не служат разрешением нам выполнять релизные действия.

Уже существующие контуры для UX: durable source preparation и reviewed publication, версии и category review, выбор исходного товара, source-only AI review, exact manual link, account health, price facts, operations/readback/quarantine, quality workspace. Новая UX-очередь, универсальная history-модель или переписывание API ради меню не нужны.

Покупательская цена и скидка Ozon остаются unknown. `imported` не означает модерацию или видимость карточки. Разрешения методов не означают фактический доступ к конкретному API. Эти границы используются в концепции и сохраняются при внедрении.

Основные источники: [активный план карточек](../OZON_CARD_UPLOAD_PLAN_2026-09-26.md), [план запуска](../OZON_LAUNCH_READINESS_PLAN_2026-09-24.md), [открытые требования](../OZON_REMAINING_WORK_2026-09-26.md), [мастер-план](../OZON_MARKETPLACE_IMPLEMENTATION_PLAN.md). ## Подтверждённые находки и гипотезы

### UX-01.2 — подтверждено чтением кода

`services/seller_attention.py` формирует beta error URL. В `routes/marketplace_listings.py::_listing_filters()` поддерживаются `marketplace`, `account_id`, `status`, `link_status`, `include_unavailable`, `search`, `page`, `per_page`. `static/marketplace-catalog-beta.js::betaDetailUrl()` возвращает только path детали. Detail получает обычный catalog URL, а `static/marketplace-detail-beta.js::switchMember()` вновь меняет адрес без исходного context. Общее `services/url_security.py::is_safe_local_path()` проверяет локальность, но не ограничивает ссылку конкретным каталогом: требуется дополнительный scoped allowlist.

Принятие: beta alias, канонический Vue и classic; поддерживаемые параметры, browser history, прямой detail, rejected external/чужой internal/duplicate query. Наблюдение UI-аудитора подтверждено механизмом в коде; новый browser reproduction пока не выполнен.

### UX-01.3 — причина пока гипотеза

В `templates/analytics.html` KPI используют `.sh-stat-grid--4`; `templates/base.html` задаёт `repeat(4, 1fr)`, breakpoint 1023 px и крупный `.sh-stat-value`. При 1024 px sidebar 260 px оставляет примерно 764 px до внутренних padding. Intrinsic minimum сетки и длинные значения могут создать переполнение. Это объяснение по CSS, а не доказанная геометрия страницы. Нужны synthetic responses, запись viewport/sidebar, измерение root scrollWidth и границ KPI **до** изменения. Ozon analytics проверялся отдельно; его результаты не закрывают этот дефект.

Предварительный scope: `templates/analytics.html` и локальный analytics stylesheet; `base.html` только при доказанной общей причине и согласованном владельце. Запрещено скрывать обрезание через `overflow-x:hidden` всего body.

### UX-01.12 — подтверждён дополнительный риск записи

`models.py::CompetitorMonitorSettings.max_products` имеет default 100000; UI показывает raw value, но input/hint утверждают 1000. `routes/competitors.py` сохраняет `max(1,min(1000,value))`; `services/competitor_monitor.py` выбирает до `min(setting,hard_cap)` строк для одного sync. Это **не подтверждённый общий лимит хранения всех групп**. Форма `templates/competitors_settings.html::save()` отправляет поле при любом сохранении, поэтому изменение только интервала/порога может уменьшить legacy 100000 до 1000.

Рекомендуемый узкий контракт: назвать эффективный лимит обработки за цикл, отдельно показать сохранённое legacy значение и hard cap, отправлять изменение лимита только при явном редактировании. При необходимости strict validation вынести в отдельный подтверждённый API-пакет; не обрезать существующие значения миграцией и не менять расписание/количество stored products ради подсказки. Проверить legacy GET, unrelated save и explicit valid/invalid limit change на временной БД.

## Предлагаемый порядок внедрения

4. **Карточка и подготовка:** .5 после .2; .6 согласованно с Ozon агентом. Обозначить все текущие states и существующие review/write gates, а не дождаться неизвестной даты полного запуска для любых read-only улучшений.
