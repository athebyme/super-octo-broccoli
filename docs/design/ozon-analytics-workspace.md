# Аналитика Ozon на Vue

Раздел отвечает на две задачи продавца: увидеть, на какую сумму и сколько единиц заказали за наблюдённый период, затем найти товары, которые дали этот результат. `revenue` аналитики не называется прибылью, начислениями или банковской выплатой. Количество единиц не называется количеством заказов. Воронка не строится из отсутствующих/удалённых метрик.

## Дизайн до реализации

Существующая «Тёплая редакция»: фон #faf9f7, поверхность #ffffff, текст #1a1a1a, вторичный #6b6b6b, граница #e8e5e1, акцент #c45d3e; реальные light/dark значения из токенов base. Inter для работы, Instrument Serif для заголовка. Левое выравнивание; нет новой палитры и декоративных изображений. Фотографии помогают узнать точные связанные товары.

```
Аналитика заказов                 период / обновить
Магазин                    заказы / начисления
Период наблюдения, актуальность и смысл показателей
Заказано на сумму | Единиц | Средняя сумма на единицу
Динамика [сумма | единицы]             выбранный день
График одной метрики + точные значения + таблица по дням
Товары: поиск / сортировка
Фото, товар и SKU       сумма       единицы      доля
Страницы
```

Выразительный элемент — ежедневная динамика одной выбранной метрики с точными значениями. Две несопоставимые шкалы не накладываются. Таблица по дням и нативный выбор дня дают доступ с клавиатуры и на телефоне. Остальной экран спокойный: показатели одной строкой, товарные строки без вложенных карточек. На телефоне показатели и строки складываются; длинные названия/деньги переносятся. Отдельные unknown и настоящий ноль; отсутствующий день не создаёт нулевую точку.

Проверка против brief: это рабочий раздел продавца на Vue в существующем приложении, без самостоятельной дизайнерской темы или сгенерированных товарных фото. Снимок и его даты объясняют расхождение между выбранным и доступным периодом. Поиск не меняет общие итоги магазина; он меняет только список товаров.

## Контракт чтения

Реализованный `GET /marketplaces/api/analytics/workspace`: exact seller/account, current core-v2 completed snapshot, period + snapshot_id + as_of, bounded product page/search/sort. Один ответ содержит coherent totals/day facts/product page и scope, поэтому UI не смешивает независимые latest ответы. Пин сохраняется при фильтрах/страницах/Back/reload; новая completed версия открывается отдельным действием либо после завершения наблюдаемой refresh-заявки. Чужой/running/удалённый snapshot не заменяется другим.

SKU — provider dimension, не количество уникальных карточек. Товар может иметь несколько SKU. Exact listing FK проверяется по seller/account/marketplace; фото/название/ссылка не берутся у чужой карточки. Текущие карточные metadata не объявляются историческими. Деньги/единицы передаются decimal string до четырёх знаков. Средняя сумма производна от наблюдённых totals и неизвестна при отсутствии числителя/знаменателя или нулевом количестве. Проценты списка — доля в той же метрике всего снимка, не в отфильтрованной странице.

Пропущенные метрики и дни — null. Суммы из day/product dimension не складываются друг с другом и не прибавляются к totals. Если снимок относится к старым датам, показывается именно его период; его агрегаты нельзя пересчитать на пересечение дат без SKU/day фактов, которых этот контракт не содержит.

Новые provider endpoints/writes, миграции и scheduler задачи не нужны. Обновление остаётся существующей durable read-заявкой с общим API ledger. GET имеет timeout/revision/abort/session guards; прежняя выборка при ошибке сохраняется с явным предупреждением. Ошибка доступа конкретного раздела не превращает весь кабинет в сломанный.

## Приёмка

Backend: exact scope/contract/fingerprint, одинаковая версия через pagination/смену дня, foreign child/listing/marketplace, missing/zero/fraction/large amount, ограничение запросов/результатов, literal Unicode поиск, stable sorting, unreachable/partial/no-data, old dates. Browser: обе темы, 320/390/768/1440, keyboard, 200% zoom, выбор метрики/дня и таблица, поиск/reset/page/Back/reload, loading/empty/error/session/late response, скрытая вкладка, реальные фото. Полная сверка с Ozon Seller и бухгалтерским отчётом остаётся отдельным gate.
