# Проверка отправлений Ozon и схем WB 20.11.2026

## Реальные чтения

Два запроса с тестовым ключом владельца выполнены через общий ограничитель Ozon из развёрнутого образа R14. Каждый запрос ограничен семью днями и одной строкой. Обогащение ответа отключено, повторных запросов и записей нет.

| Запрос | Результат |
| --- | --- |
| `/v4/posting/fbs/list` | HTTP 200, одна строка прошла текущую нормализацию. Провайдер прислал поле `scanit` строкового типа на верхнем уровне отправления при `with.barcodes=false`. |
| `/v3/posting/fbo/list` | HTTP 200, текущая схема приняла пустую страницу за проверенный период. |

Факты по FBS подтверждают текущее чтение. Для генерации этикеток нужны актуальные поля запроса и ответа, статусы задания и проверка принадлежности PDF отправлению. Действующая политика проекции исключает хранение штрихкодов. [Обновление Ozon](https://dev.ozon.ru/news/800-Podderzhka-novoi-etiketki-scanit-i-migratsiia-metodov-v-Seller-API/) · [Ответ модератора об асинхронной генерации](https://dev.ozon.ru/community/2371-Metod-dlia-sozdaniia-zadanii-na-formirovanie-etiketok/)

В развёрнутом R14 локальные списки заказов, возвратов и отмен для точного аккаунта ответили HTTP 200. При просмотре последних семи дней экран использовал дату старой недельной загрузки 18–24 сентября. В той же области аккаунта найден завершённый запуск за 22 октября — 20 ноября, который охватывает весь выбранный диапазон 14–20 ноября. Исправление привязывает подпись к датам фактического покрытия. При отсутствии полной загрузки интерфейс сообщает об этом даже при пустом списке.

## WB-EDIT-02

На текущих данных продавца вызовы точного имени, subjectID и чтения схемы массовой формы завершились HTTP 200 для обеих категорий. Для «Свечи эротик» (5880) массовая форма получила 33 определения полей, для «Мастурбаторы мужские» (5070) — 32. Запрос схемы категории вне точного набора выбранных товаров получил HTTP 403. Проверка шла в отдельном процессе с базой SQLite только для чтения и запретом сетевых запросов. Историческая причина ошибки `Subject не найден` остаётся неизвестной.

Отдельно подтверждено, что при смене категории запоздавший ответ предыдущего запроса мог очистить поля или заменить сообщение актуальной формы. Эта гонка относится к браузерному состоянию. Её проверка использует управляемый порядок ответов без записи карточек и запросов к WB.

## Внешняя приёмка

У тестового ключа есть заявленные права на чтение отзывов и вопросов. Оба точечных запроса к Seller API отправили по одному разу и получили HTTP 403. Причина отказа остаётся неизвестной. Для покупательской цены найдена официальная колонка «Цена на сайте» в отчёте по товарам. Нужны актуальный контракт получения отчёта и сверка одного собственного SKU с кабинетом. [Описание отчёта Ozon](https://dev.ozon.ru/news/787-Vazhnye-izmeneniia-v-metodakh-otchetov-Seller-API/)

Проверены 21 черновик точного аккаунта, записи загрузок и связанные данные товара. Среди 14 черновиков без связи с опубликованной карточкой ни один не готов к отправке. Девять содержат положительные сохранённые размеры упаковки, но актуальность источников требует подтверждения. Семь связанных актуальных схем требуют значения для ТН ВЭД и маркировки. В проверенных черновиках для них нет подтверждённых значений. Реальное создание и модерация остаются открытыми.

## Повтор браузерной проверки

Первый образ прошёл 36 проверок раскладки Ozon и 7 из 8 этапов UX. Полный сценарий WB зарегистрировал необработанный JavaScript-ответ, поэтому версия отклонена. В проверке гонки ограничили подмену HTTP точным маршрутом чтения схемы и вынесли её состояние отдельно от смонтированной формы. Отдельное сравнение в Chromium снова воспроизвело гонку на старом редакторе, а исправленный редактор прошёл полный сценарий с пятью проверками гонки и без ошибок JavaScript. Тест сообщения пустого состояния сверяется с фактически показанным действием. Изменения повторного пакета затрагивают проверочные файлы и их манифест.
