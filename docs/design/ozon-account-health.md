# Ozon: состояние магазина и диагностика обновлений

## Цель и план

W8 требует различать доступность приложения, обработчик фоновых задач, подключение кабинета, свежесть каждого раздела и возможность конкретной записи. Новый экран показывает эти факты отдельно; отсутствие ошибок не выдаётся за подтверждённое здоровье. Прежний rollout/WB parity dashboard остаётся отдельным техническим инструментом и не становится разрешением на публикацию.

1. Добавить наблюдаемый scheduler heartbeat: существующий singleton записывает bounded atomic heartbeat раз в 30 секунд, HTTP/CLI проверяют одновременно свежесть и владение process lock. PID сам по себе не доказывает работу. SKIP_SCHEDULER/unknown/missing/stale отдельно от healthy; проверка не запускает задачи и не пытается захватить владение.
2. Построить read-only exact seller/account read model из существующих локальных таблиц. Для catalog, analytics, fulfillment, finance, reviews, questions отдельно возвращать latest attempt, last completed snapshot/window, age, overdue schedule, pending intent и provider cooldown. Частичная загрузка не заменяет последний completed факт; capability denial не объявляется нулём обращений. API не расшифровывает credentials и не вызывает Ozon.
3. Дать продавцу страницу Vue «Состояние магазина» с датами и конкретными переходами в нужный раздел/настройки/операцию. Обновление экрана — локальный GET, не provider refresh. Сохранить account context, polling только видимой вкладки, timeout/abort/exact-scope guards, понятные unknown/error states и последнюю успешную выборку.
4. Добавить операторскую read-only CLI-проверку того же контракта с JSON и exit status. Бounded DB read/deadline, owner-scoped IDs, no credentials/customer text/payloads. Она позволяет внешнему наблюдателю обнаружить остановку scheduler, даже когда сам scheduler не работает.
5. Проверить реальные классы отказов на изолированном стенде: lock free/held/stale/rotated, active→waiting→fresh, access denial, expired credentials, old window, terminal uncertain operation, foreign scope, SQL read deadline. Проверить обе темы/узкие экраны и production GET. Развернуть конкретный прошедший проверки образ.

## Границы W8

Этот этап создаёт измеримый сигнал и понятную диагностику. Он не закрывает внешнего наблюдателя, доставку автоматических аварийных уведомлений, off-host/key/media recovery, согласованные RPO/RTO и полный disaster-recovery drill. Отправка редких агентных этапных статусов в настроенный deployment Telegram остаётся прежней командой; новые периодические Telegram-рассылки этим этапом не включаются.

Последующий local-operations пакет добавляет отдельные host timer и инфраструктурные alerts, сохраняя эти границы account-health: [дизайн](local-operations-watchdog.md). Внешнее хранилище отложено владельцем 26.09; local observer не обнаруживает потерю своего хоста.

Сигнал наблюдения не меняет write flags, due time, попытки, proposal/operation state или сроки provider cooldown. Автоматический повтор неизвестной записи запрещён. Никаких live API probes для отрисовки состояния; старое наблюдение маркируется датой.

## Дизайн

Сохраняется текущая Seller Hub тема и её semantic tokens: фон `#faf9f7`, поверхность `#ffffff`, текст `#1a1a1a`, пояснения `#6b6b6b`, акцент `#c45d3e`, положительный статус `#2e7d54`; dark берётся из тех же tokens. Шрифт интерфейса и serif заголовок наследуются из shell. Новая палитра и иллюстрации не нужны: смысл этой страницы — достоверные даты и следующий шаг.

Композиция: название магазина и явный момент проверки → две компактные строки подключения/фонового обработчика → единый список шести разделов с последней полной загрузкой, текущим ожиданием и ссылкой → список операций, где требуется решение. На мобильном статус и время переходят под название. Иконки — из существующего SVG-набора, статус всегда подписан словами.

Критика плана: большой общий зелёный score или одинаковые декоративные metric cards скрыли бы различия. Поэтому основная структура — сравнимые строки разделов, а предупреждение появляется рядом с конкретным фактом. Технические PID, lock paths, opaque error bodies, credential fingerprints и сырые enum в seller flow не выводятся.

## Проверка дизайна

Стенд: осмотрены desktop light, mobile dark и список неподтверждённых операций; сохранена общая типографика, существующие иконки и semantic colors. После проверки контраста ссылки используют `--accent-strong`; длинные названия переносятся без горизонтального скролла. Клавиатурный запуск локальной проверки, focus-visible, ошибки `role=alert`, начальная загрузка `role=status`, сохранение наблюдения при потере сети проверяются в браузере. Проверка по [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) относится к новому экрану, не является заявлением о полном аудите всей legacy-оболочки.

Интеграционная проверка выявила, что общий Flask after_request заменял явный `private` своим более общим `no-store`. Hook теперь сохраняет `private` и глобальные `no-store/no-cache`; public cache исключение по-прежнему существует только для двух подписанных media endpoints с явным public response.
