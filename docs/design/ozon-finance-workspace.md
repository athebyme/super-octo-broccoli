# Финансы Ozon: журнал начислений на Vue

Цель — продавец видит суммы за выбранный период, понимает состав конкретного начисления и переходит к связанному товару/отправлению. Снимок Ozon не выдаётся за прибыль, выплату на банковский счёт или текущую покупательскую цену.

Дизайн сохраняет тему Seller Hub: `--bg`, `--bg-card`, `--text`, `--text-muted`, `--border`, `--accent`; светлая основа #faf9f7, поверхность #ffffff, текст #1a1a1a, вторичный #6b6b6b, граница #e8e5e1, акцент #c45d3e. Точные runtime-цвета берутся из tokens, включая dark. Существующие заголовочный serif и основной sans-serif сохраняются. Никаких новых шрифтов/иллюстраций для денежных данных: полезное изображение здесь — фото точно связанного товара.

Макет: заголовок и обновление → магазин/период → состояние снимка → фильтры → отдельный ряд сумм для каждой валюты → журнал начислений. В журнале дата/номер слева, товар или назначение в центре, подписанная сумма справа. На телефоне строка последовательно складывается в один столбец. Вместо широкой таблицы и одинаковых KPI-карточек — компактная денежная ведомость с табличными цифрами. Названия типов и пояснения остаются читаемыми; API field names — только в раскрываемом источнике.

Деталь открывается native dialog: основная сумма, номер и дата, точная ссылка на отправление, товары с фото, отдельная постраничная расшифровка удержаний/услуг и источник/время. Поясняющие компоненты не прибавляются повторно и не обязаны складываться в top-level сумму. Неизвестная валюта/сумма остаётся неизвестной, numeric zero сохраняется, каждый currency total отдельный. При фильтре по типу выбирается целое начисление, содержащее этот компонент, — это явно подписано.

URL сохраняет period/search/category/sign/type_id/page/fact_id, completed snapshot_id и as_of и страницы состава/расшифровки; работают reload, Back/Forward, Escape, возврат фокуса. GET timeout 10s, abort/revision/exact-account guards; при ошибке предыдущая выборка явно обозначена. Потерянный refresh POST не повторяется, общий durable refresh только ставит read-заявку. Сессия останавливает polling и даёт вход. Неполное покрытие периода и failed attempt показываются отдельно от последнего готового snapshot. Отсутствие снимка не объявляется нулевым балансом.

Снимок и точные даты периода закрепляются после первого чтения: новая фоновая загрузка и смена календарного дня не меняют суммы между страницами. Удалённый/недоступный снимок даёт 404 без подмены другим; есть действие «Открыть актуальные данные». Смена периода, явное открытие последних данных и завершение наблюдаемой активной refresh-заявки снимают закрепление. Начальный статус старой завершённой заявки сохраняет закрепление. После потерянного ответа POST подтверждённое GET completed снимает закрепление; POST не повторяется.

Backend: compact list фиксированным числом запросов отдаёт не более трёх товаров и трёх компонентов на строку плюс полные counts. Detail читает отдельно bounded страницы товаров/компонентов. Все child/FK/ссылки повторно проверяются по seller/account/marketplace; чужая/исчезнувшая связь не даёт название или фото. Search трактует `%`/`_` буквально; malformed/duplicate/unknown query отклоняются до чтения. Последний completed snapshot, Decimal/sign/currency и существующий provider read contract не меняются.

Приёмка: totals per currency без double count; фильтр по типу без умножения суммы на число компонентов; старый completed при pending/failed/новом периоде; foreign child/FK; большие составы с достижимой последней страницей; query budget; ноль/отрицательные/длинные суммы; mobile 320/390, desktop 1440, обе темы; slow/out-of-order/session/lost POST; реальный локальный журнал и фото; выборочная независимая read-сверка Ozon при подтверждённом endpoint-контракте. Полная бухгалтерская сверка с отчётом Ozon остаётся самостоятельным условием, UI её не заменяет.

## Выгрузка выбранной выборки

Кнопка «Скачать Excel» доступна для успешно загруженной закреплённой выборки и скачивает все её страницы. Отдельные листы показывают metadata/покрытие/фильтры, валютные totals, parent начисления, товары и explanatory компоненты. Чужие child/FK не экспортируются; отсутствие связи не подменяется похожим товаром. Файл из неполного покрытия помечен `partial` и явным текстом; пустая выборка не объявляется нулевым балансом. Все суммы independently пересчитаны из parent Decimal и сравнены с UI totals.

Read transaction защищает от pruning между чтением snapshot и children, закрывается до генерации файла. Read-only endpoint не вызывает Ozon, не создаёт jobs и не меняет данные. Бюджеты: 10 000 фактов, 50 000 child rows, 16 MiB text/output, 20s; typed 422 вместо усечения. XLSX write-only/temp cleanup, no-store; клиентский timeout 30s, cancel и scope/revision/session guards не скачивают поздний или чужой ответ.

XLSX выбран, чтобы типизировать идентификаторы и текст явно: CSV может интерпретировать непроверенное содержимое как формулы, универсального экранирования для всех редакторов нет ([OWASP](https://owasp.org/www-community/attacks/CSV_Injection)). Все текстовые ячейки имеют explicit string type, никаких формул/макросов/active links не создаётся. [Microsoft](https://support.microsoft.com/en-us/excel/format-numbers-as-text) ограничивает numeric precision 15 значащими цифрами: длинные IDs всегда текст, суммы дополнительно имеют exact text column; значения выше порога также текст в основной колонке. [openpyxl write-only](https://openpyxl.readthedocs.io/en/stable/optimized.html) позволяет формировать листы без полного дерева ячеек в памяти.
